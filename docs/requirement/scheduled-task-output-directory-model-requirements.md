# 定时任务工作目录与模型配置需求

日期：2026-10-03  
状态：需求说明

## 1. 背景与目标

定时任务在无人值守时执行。自动化任务应拥有独立于桌面当前 Profile 的工作目录；用户切换桌面工作台后，任务仍在自己的目录中执行，并在需要时于该处保存和查找产物。不同任务也应能按复杂度选择模型与思维强度。

目标是让**每个任务的工作目录、模型档位由任务自身持有**。手动“立即运行”与定时触发遵循同一规则，不依赖运行时桌面选择的 Profile。

## 2. 代码现状与缺口

- `src/shared/automationTaskTypes.ts` 已有可选 `modelOverride`，`automation_tasks.model_override` 已持久化；`electron/butler/butlerInvoker.ts` 创建会话时会使用它。但 `ButlerTaskSettings.tsx` 没有模型选择入口，IPC 对模型字符串也没有可用性校验。
- 任务没有工作目录字段。`butlerInvoker.ts` 创建会话时读取活动工作目录 Profile；模型消息、事件位置和工具工作目录又存在直接读取 `getWorkDir()` 的路径。因此自动化任务当前复用了桌面工作台状态，安全审核 Agent 和工具路径检查也可能据此判定目标是否位于工作区内。
- `AgentReasoningEffort` 已定义为 `off / low / medium / high / max`，任务定义和执行入口尚无任务级思维强度配置。

## 3. 用户场景

1. 用户在桌面 Profile A 下创建“日报”任务并设定任务目录 A，之后切换桌面到 Profile B。下一次定时运行仍使用任务目录 A；如果任务产生了产物，历史运行记录仍能定位对应产物。
2. 用户将简单的只读汇总任务设为低成本模型、思维强度 `off` 或 `low`；复杂分析任务使用另一模型和更高档位。两个任务互不影响，也不随聊天界面的模型切换改变。
3. 配置目录被删除、不可写，或指定模型被禁用时，任务显示明确失败原因；不得悄悄改用当前 Profile 或其他模型，以免产物写错位置或费用超出预期。

## 4. 功能需求

### FR-01：任务级输出目录

- 新建、编辑任务时提供“任务工作目录”选择和只读路径展示；它是自动化任务自己的工作台，不是桌面 Profile 选择器。支持清除或重新选择。列表卡片展示目录摘要，详情能查看完整路径。
- 创建任务时可将当时桌面工作目录作为初始建议值，供用户直接采用或修改；保存后将规范化的本机绝对路径归属到任务配置，不保存会随桌面切换改变的 Profile 引用。自动任务运行中或之后切换桌面 Profile，不改变该任务目录。编辑并保存任务目录后，后续运行使用新值；已经开始的运行继续使用开始时读取的任务配置。
- 新任务必须有有效的任务工作目录（创建表单可预填初始值）。旧任务迁移时保留原行为并提示“尚未设置任务工作目录”；不得把迁移时的活动 Profile 静默写进任务配置。旧任务在选择任务目录前沿用兼容策略，设置后转为任务独立目录。
- 主进程负责路径校验：非空、绝对路径、规范化、目录存在与可访问性；对软链接或目录替换引起的越界风险沿用现有工作目录安全约束。运行开始时重新校验，失败时记录明确错误并停止，不回退到活动 Profile。具体写入是否成功由任务实际使用的能力和现有权限规则决定。
- 任务工作目录是该自动化任务执行时的固定工作区。执行上下文必须将任务配置的目录传入工作区快照、工具路径事实探测及安全审核 Agent；不得沿用或回退到桌面当前 Profile，否则任务目录内的目标可能被误判为工作目录外。会话数据、事件日志与任务工作目录的具体存储关系应保持一致，不能在执行中读取桌面 Profile 引发漂移。
- 如任务产生了产物，运行记录或运行会话应保留该次使用的目录，便于定位；不得仅从任务当前配置反推历史目录。产物的文件名、覆盖行为和组织方式由具体任务或其产物能力决定。

### FR-02：任务级模型与思维强度

- 新建、编辑任务时提供“模型”和“思维强度”选择。模型选项来自已启用、已配置可用服务的模型列表；展示模型名称及服务，避免同名模型来源不明。
- 思维强度选项遵循模型能力与运行时支持范围；不支持思维的模型只允许 `off`。UI 约束之外，主进程在创建、更新、每次运行前再次校验。
- 新建任务时预选当前桌面使用的模型及其思维强度，用户可直接保存，也可改选。保存时将预选值写入任务配置，此后桌面模型切换不改变该任务。若当前模型不可用于后台任务，预选一个可用的默认模型；没有可用模型时提示用户先完成模型配置。界面不额外展示费用提示。已存在任务的 `modelOverride` 保持原值；缺失模型配置的旧任务按兼容规则运行，并在编辑页展示实际继承值，不在迁移时自动改写任务配置。
- 模型标识应能确定实际服务路由；如果现有 `modelOverride` 只能标识模型而不能唯一标识服务，应补充服务身份或冻结解析结果，避免服务配置变化后意外切换供应商。密钥本身不写入任务表。
- 本次运行的模型、服务、思维强度及实际降级结果要进入运行/调用记录。模型不可用或凭据失效时明确失败，不自动换到更贵的模型；若现有运行时规则会降档，必须可见并留痕，不静默调整。

### FR-03：执行一致性

- 调度触发、手动立即运行、失败重试都读取同一份任务配置，并在准入后、会话/调用创建前形成运行快照。排队期间任务被编辑时，以真正开始执行时读取的版本为准；开始后保持不变。
- 任务详情和历史记录能够区分“当前设置”与“该次运行实际使用的设置”。失败记录包含触发方式、目录/模型解析失败原因；成功记录可追溯输出位置和模型用量。
- 更改任务目录或模型不迁移历史产物，不修改已开始的运行，也不重写旧运行记录。

## 5. 输出目录与安全审核的边界

任务工作目录确定自动化任务执行时的工作区，不规定任务必须写入文件，也不决定写入什么。只读任务、仅发送通知的任务可以没有文件产物；需要产物的任务由自身业务逻辑决定内容、格式和命名。创建时从桌面目录带入的初始建议值在任务保存后即成为任务自身配置，不再与桌面 Profile 保持联动。

任务目录进入工作区/安全审核上下文后，只影响路径归属事实（例如目标是否位于任务工作区），不授予本来被拒绝的工具权限，也不改变风险策略。当前 automation lane 中，`write_file` 仍由 `automation-write-deny` 锁定拒绝；设置任务目录本身不能放行它。需要由任务实际工具对应的既有安全规则决定能否执行。

## 6. 非功能与数据要求

- 数据层需为任务增加目录和思维强度字段，并为运行增加必要的配置快照/产物定位字段；迁移可重复执行，旧任务不丢失、不被悄悄改写。
- IPC 只接收意图；路径和模型能力判断由主进程完成，现有工具权限判断继续由原有机制负责。错误返回可定位到具体字段并在设置页展示。
- 界面文案进入现有 i18n；路径较长时可截断显示，但完整路径可查看。
- 不把绝对路径、模型密钥或完整产物内容写入对外通知；本地运行记录可保存定位所需信息。

## 7. 验收标准

1. 在桌面 Profile A 下创建任务并将任务工作目录设为目录 A、模型设为 M、思维强度设为 low；切换桌面 Profile 到 B 后触发任务，执行上下文、安全审核 Agent 和运行快照仍使用目录 A/M/low。如果任务产生了产物，产物位置与 A 关联。
2. 任务运行中修改为目录 C、模型 N；本次继续使用 A/M，下一次使用 C/N。
3. 手动运行与定时触发的目录、模型、思维强度解析一致。
4. 任务目录不存在、不可访问或被替换，模型被禁用、路由/凭据失效，均形成可见失败记录；目录异常时不会回退到桌面当前 Profile，模型异常时不会回退到其他模型。实际写入失败由具体任务记录相应错误。
5. 不支持思维的模型无法保存非 `off` 档位；运行时能力变化产生明确失败或可见降档记录。
6. 旧任务升级后仍可读取与编辑；任务原有 `modelOverride` 不丢失，未配置任务目录的兼容行为明确展示。
7. 不产生文件的任务也能使用固定目录运行；设置目录不会改变既有工具授权结果。

## 8. 建议实施边界与待定决策

建议按“数据/IPC 与校验 → 设置页 → 执行快照与路径贯通 → 运行记录与历史定位”推进，并为调度与手动入口、Profile 切换、迁移和失败路径增加测试。

评审时需决定：① 旧任务未配置任务目录时的具体兼容期限。本文建议新任务表单预填当前桌面目录作为初始建议值，用户可直接保存；旧任务保留兼容行为并提示设置独立目录。
