# Agent Runtime 并发准入策略

**状态：** 已决策，按实际运行数据复查  
**决策日期：** 2026-10-02  
**范围：** 桌面、微信、飞书、自动化 Agent turn 的应用级在途准入，以及安全审批 Agent 与父 turn 的容量边界。

本文是当前有效的产品策略记录。历史问题清单、旧架构规划中的“速率与配额”表述用于解释决策来源，不覆盖本文。

## 1. 问题与决策依据

应用级准入控制的是**同时持有运行资格的 Agent turn 数量**。它不是 CPU、内存、模型服务配额或 token 预算的计量器。Agent turn 大量时间用于等待 LLM 网络响应；目前又没有把工具执行放进隔离沙箱，因此没有证据支持原先较低的全局并发值。

统一准入实现曾增加每小时启动数：全局 120 次，桌面 120 次，微信和飞书各 60 次，自动化 30 次。该限制来自 2026-09-20 统一准入实现：自动化沿用了旧管家任务每小时 30 次的限制，其余数值在实现中被扩展为全局与 lane 配额。没有找到这些数值对应的资源预算或产品依据；桌面受理和内层审批还会重复计数。因此不再以 Agent turn 启动次数作为应用准入条件。

## 2. 当前策略

| 范围 | 上限 | 说明 |
| --- | ---: | --- |
| 所有 lane 合计 | 100 个在途资格 | 所有 lane 共用的总上限 |
| 桌面 | 100 个 | 受全局总上限约束；可使用其他 lane 未占用的容量 |
| 微信 | 8 个 | lane 独立上限 |
| 飞书 | 8 个 | lane 独立上限 |
| 自动化 | 4 个 | lane 独立上限 |
| 后台任务合计 | 100 个 | 只作为不额外收紧总量的子上限；自动化仍受其 lane 上限 4 约束 |
| admission 等待队列 | 100 项 | 等待首次取得普通 turn 准入的申请；满后新的排队申请以 `queue-full` 结束 |

准入**不再按小时限制启动数**。已有 `admission.policy.globalHourlyStarts` 配置和旧状态中的小时计数不参与判定；状态读取时会忽略旧小时计数字段。

安全审核 Agent **不申请上述普通 turn 的全局或 lane 准入名额**。父 turn 在审批等待期间继续持有其普通名额，审批完成后直接继续当前 turn，不 park、不恢复准入、不重新排队。安全审核 Agent 由独立的 `ApprovalAdmission` 管理；当前桌面配置为 4 个并发审批、32 个等待项、每个父任务最多 2 个在途审批。它受审批自身的超时/取消语义约束，这些值不占普通 turn 的 100 个名额。

## 3. 审批等待中的普通准入

普通准入只在 turn 启动时申请一次。进入安全审批等待不会释放该资格；审批通过、拒绝或取消都在同一个 turn 生命周期内结算，不产生新的 admission 申请。

审批回答者的容量由独立审批池控制；turn 内并行工具和审批候选的等待由其既有信号量/取消机制管理。审批等待不改变工具执行超时、用户确认等待或 turn 取消语义。

## 4. 排队与入口边界

等待队列当前是进程内共享队列，仅承载尚未取得普通准入资格的申请，并按申请先后顺序竞争可用容量。用户取消 turn 时，其等待项应移除。审批中的 turn 不进入该队列。`queue-full` 是容量拒绝，不是等待超时。

不同调用入口仍可能选择不同 disposition（排队或立即拒绝）；本策略确定准入上限，不应被解释为“所有入口都保证排队”。如需统一入口行为，应另行修改和验收其受理契约。

## 5. 实现边界与复查

- 默认值实现在 `electron/runtime/callAdmission.ts`；持久化兼容在 `electron/storage/callAdmissionStore.ts`。
- `approvalReservedSlots` 曾是普通准入里的额外保留位；它已移除。生产安全审核使用独立审批池；父 turn 在审批等待期间继续持有普通名额，不再依赖普通 gate 的 park/resume 状态转换。
- 后续根据真实等待数、`queue-full` 拒绝数、lane 活跃数和取消情况复查队列 100 与 lane 上限；不因抽象的 CPU、token 或“防爆”理由恢复未经验证的每小时配额。

## 6. 决策历史

| 日期 | 决策 |
| --- | --- |
| 2026-10-02 | 全局并发改为 100；微信和飞书各 8；自动化 4；移除 Agent 小时启动配额；审批恢复不设固定等待超时；共享 admission 队列上限改为 100。安全审批使用独立容量池，不占普通 turn 名额；移除普通 gate 的审批保留位。后续按运行数据复查。 |
| 2026-10-02 | 基于 `application admission park failed` 的实际会话记录，审批等待期间父 turn 保留普通准入名额；移除 turn 生命周期内的 admission park/resume 与审批后恢复排队。普通名额为 100，暂无数据证明释放审批等待名额的收益值得承担状态转换复杂度。 |
