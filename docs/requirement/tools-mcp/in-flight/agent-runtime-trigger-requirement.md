# Agent Runtime 通用触发器需求说明书

> 状态：需求草案，待评审  
> 范围：为 Agent 提供一次性触发器工具；runtime 在指定事件发生时，向注册时指定的会话排队一条唤醒消息。  
> 本文描述用户可见行为与验收边界，不规定内部实现。

## 第 0 层：决策层【人必读】

**一句话：** Agent 可以登记一个未来事件；事件发生后，runtime 将事件信息送到指定会话，让该会话有机会继续处理。

**价值与不做的后果：** 多会话协作、长时间任务和外部消息常常需要稍后回到原会话处理。没有通用触发器时，Agent 通常只能不断轮询任务状态，才能发现另一个会话是否完成、执行是否达到检查点、进程是否结束或指定时间是否到来。轮询会反复消耗 Tokens，并把重复检查及中间结果留在上下文窗口中；等待时间越长，浪费越多，也会挤占真正处理任务所需的上下文。用户还可能需要手动盯守或重复交代。

**需要评审人决定：** 当前没有新增产品决策项；本文关键体验取值来自本轮用户确认。

**不需要评审人决定：** 触发器为一次性；会话 step 阈值触发器可选择异步或同步处理；异步不暂停目标会话，同步在检查点暂停目标会话并等待接收会话处理；Agent 可直接注册；五类场景均纳入首期；支持跨会话注册；未触发项在应用重启后恢复；IM 触发消息传入正文和必要上下文。

### 已确认取值

| 决策 | 取值 | 用户可见结果 |
|---|---|---|
| 命中后生命周期 | 一次性 | 同一注册最多唤醒一次；命中后不再等待后续事件 |
| 会话 step 阈值处理模式 | 注册者可选异步或同步；Turn 完成仍为异步通知 | 异步只排队并让目标会话继续；同步在 step 检查点暂停目标会话，等接收会话完成处理后再恢复 |
| 接收会话正忙 | 唤醒消息排队，接收会话不被打断 | 接收会话完成当前 Turn 后处理唤醒；同步模式下目标会话保持暂停直到处理完成 |
| 注册权限 | Agent 可直接注册 | Agent 无需逐次请求用户批准即可登记触发器 |
| 触发器归属 | 可跨会话登记，runtime 保留 | A 会话可以登记监听 B 会话的事件，并指定唤醒 A |
| 会话事件 | Turn 完成、累计 step 数达到阈值 | 可等待某轮结束，也可在执行达到指定进度时检查 |
| 重启恢复 | 恢复未触发项 | 应用关闭或重启不应悄然丢弃仍有效的等待 |
| IM 载荷 | 消息正文及必要上下文 | 被唤醒 Agent 可以理解并处理收到的消息 |

## 第 1 层：需求概要【人机共读】

### 1. 目标

1. Agent 能通过统一工具登记一次性触发器，声明触发条件与接收唤醒的会话。
2. runtime 能监听目标事件，事件命中时向指定会话排队唤醒消息和对应事件信息。
3. step 阈值触发器可选择异步或同步：异步模式不暂停目标会话；同步模式在命中检查点暂停目标会话，接收会话完成处理后再恢复。Turn 完成触发器为异步通知。
4. 未触发的有效触发器在应用重启后继续等待。
5. 支持会话 Turn 完成、会话 step 阈值、受 runtime 管理的进程终止、IM 消息到达和指定时间到达五类事件。

### 2. 用户故事

- 作为协作 Agent，我在 B 会话完成审核 Turn 后收到唤醒，以便查看结果并继续后续工作。
- 作为监督 Agent，我在 B 会话执行到指定 step 数时收到唤醒，以便检查执行是否偏离目标。
- 作为发起长进程的 Agent，我在进程终止后收到退出信息，以便解释或处理结果。
- 作为 IM 自动化 Agent，我在符合注册条件的 IM 消息到达时收到消息正文及必要上下文，以便响应消息。
- 作为计划任务 Agent，我在指定时间到达后收到唤醒，以便启动工作。

### 3. 范围清单

**本期做**

- 通用的一次性触发器登记、等待、命中、投递与完成行为。
- 指定接收会话与事件对象；允许跨会话监听并唤醒。
- 五类事件：Turn 完成、累计 step 阈值、受 runtime 管理的进程终止、IM 消息到达、指定时间到达。
- 事件载荷按类型向 Agent 提供处理事件所需信息；IM 至少包含消息正文与必要上下文。
- step 阈值触发器支持异步排队或同步暂停目标会话；Turn 完成、进程终止、IM 消息和定时触发采用异步通知，不暂停其来源对象。
- 应用重启后恢复未触发且仍有效的触发器。
- 注册、取消、命中、投递失败等结果对注册 Agent 可判定，避免静默丢失。

**明确不做**

- 周期性 / 重复触发器、日历规则或复杂 cron 表达式。
- 触发器管理 UI、用户配置开关、通知面板或独立管理工作台。本期行为可通过 Agent 工具与会话消息观察。
- 对未由 runtime 管理或无法确认归属的任意外部进程提供退出监听。
- 允许触发器打断当前 Turn、抢占工具调用或取消目标会话正在执行的任务。
- 用触发器替代 IM 链路已有的身份识别、权限、安全策略与用户授权。

**未来再引入**

- 重复计划、周期任务、触发条件组合、触发器优先级与配额管理。
- 面向用户的触发器浏览、编辑和审计界面。
- 更多事件源（如文件变化、系统通知或外部 webhook）。

## 第 2 层：行为规格【人机共读】

### 4. 术语

| 术语 | 定义 |
|---|---|
| 注册会话 | 发起触发器注册的 Agent 所属会话；跨会话场景中也称发起方会话 |
| 目标对象 | 触发器监听的会话、进程、IM 消息流或时间点 |
| 接收会话 | 注册时明确指定、命中后接收唤醒消息的会话；可以与注册会话相同 |
| Turn | 一次 Agent 响应过程，从开始处理输入到本轮结束 |
| step | Agent 在一个 Turn 中推进任务的一步；阈值按目标会话累计执行步数计算，注册时须明确计数起点 |
| 唤醒消息 | runtime 投递给接收会话的消息，说明触发原因、事件时间和可用事件信息 |

### 5. 通用行为规则

| ID | 规则 |
|---|---|
| BR-01 | 注册时必须指定一种事件条件、目标对象、接收会话以及该事件需要的参数。缺少必要信息或目标不可解析时，注册失败并向 Agent 返回可理解的原因；不得静默建立不完整触发器。 |
| BR-02 | 每个触发器只允许一次命中。事件命中后，runtime 将触发器转为已触发并停止监听；即使唤醒投递随后失败，也不得因重复事件产生多条唤醒。 |
| BR-03 | 注册会话可指定另一个会话作为目标或接收会话。runtime 必须保留注册者、目标和接收会话之间的关联，使事件不会误投到其他会话。 |
| BR-04 | 目标事件发生时，runtime 向接收会话追加一条可识别为触发器唤醒的消息，并附上事件类型、目标、发生时间和该类型规定的事件载荷。 |
| BR-05 | 注册者可为 step 阈值触发器选择异步或同步模式。异步模式将消息排入接收会话队列，目标会话照常执行；同步模式在 step 检查点暂停目标会话，并等待接收会话完成本次唤醒处理后再恢复目标会话。Turn 完成、进程终止、IM 消息和定时触发均为异步通知，不暂停来源对象。 |
| BR-06 | 接收会话正在运行时，唤醒消息排在其当前 Turn 之后；不得打断接收会话当前生成或工具执行。同步模式下目标会话在等待期间保持暂停；接收会话空闲时可开始处理该事件。 |
| BR-07 | runtime 不保证 Agent 一定采取行动；它保证按模式投递事件。异步模式给接收会话处理机会；同步模式保持目标会话暂停，直到接收会话完成本次处理或同步等待以明确的终态结束。 |
| BR-08 | 未触发触发器在应用重启后恢复等待。重启期间可观测到的事件不得导致同一触发器重复唤醒；若事件无法可靠追溯，按对应事件类型的失败边界向 Agent 明确呈现。同步等待中的目标会话也须恢复为可判定状态，不得静默继续执行或永久挂起。 |
| BR-09 | Agent 可取消自己注册的未触发触发器；取消成功后，之后的匹配事件不再唤醒接收会话。已命中或已取消的触发器不能再次取消为有效等待。同步模式下取消已命中的等待后，目标会话按该触发器登记的超时/取消策略恢复或进入明确终态。 |
| BR-10 | Agent 能查询其触发器的可判定状态：等待中、已命中/已投递、处理中、已完成、已取消、已过期或失败。查询范围受会话归属约束，不得泄露其他无关会话的触发器信息。 |

### 6. 事件类型与触发条件

| ID | 类型 | 命中条件 | 唤醒载荷最低要求 |
|---|---|---|---|
| EVT-01 | 会话 Turn 完成 | 指定会话的当前 Turn 进入终态。若注册时指定某个正在运行的 Turn，只在该 Turn 完成时命中；目标 Turn 已结束或不存在时注册失败。 | 目标会话标识、Turn 标识、结束时间、可用的完成状态与结果摘要 |
| EVT-02 | 会话累计 step 阈值 | 指定会话自注册时明确的计数起点起，累计完成 step 数首次达到阈值。超过阈值的事件也视为命中，不要求精确落在该整数瞬间。注册者必须选择异步或同步；同步命中后在该检查点暂停目标会话。 | 目标会话标识、实际累计 step 数、阈值、对应执行进度信息 |
| EVT-03 | 进程终止 | 指定的、由 runtime 管理且已确认归属的进程结束，不论正常退出还是异常退出。 | 进程标识、退出状态、退出码（若有）、终止原因和可用的输出摘要 |
| EVT-04 | IM 消息到达 | 指定 IM 来源与匹配条件的新消息到达。注册必须限定消息流及可选过滤条件，不能隐式监听所有账户或所有消息。 | 消息正文、发送者与会话上下文、来源渠道、消息时间及可用的回复关联信息 |
| EVT-05 | 定时到达 | 注册时指定的绝对时间到达。时间值必须包含明确时区或明确为绝对时间，避免本地时区歧义。 | 计划时间、实际触发时间及注册时声明的任务提示 |

### 7. 触发器状态与优先规则

触发器状态对 Agent 表现为以下互斥结果：

| 状态 | 含义 | 后续行为 |
|---|---|---|
| 等待中 | 已成功登记，条件尚未满足 | 继续监听；重启后恢复 |
| 已命中/已投递 | 条件满足，唤醒消息已进入接收会话队列 | 不再监听，不重复投递 |
| 已取消 | 注册 Agent 主动取消 | 不再监听、不投递 |
| 已过期 | 条件已不可能发生或时限已过 | 不再监听；可查询终止原因 |
| 失败 | 注册、恢复或事件投递无法完成 | 暴露稳定、可理解的失败原因；不得伪报成功 |

裁决顺序：成功取消先于尚未处理的后续事件；一次命中后状态终结；事件发生与取消同时竞争时，只允许一个结果获胜，并保证不会重复唤醒。接收会话队列暂不可用时，runtime 保留待投递状态并重试；达到失败终态时须可查询。

## 第 3 层：验收与边界【机｜人工可跳过】

### 8. 验收标准

| AC | 验收断言 |
|---|---|
| AC-01 | Agent 提交有效注册后能得到可引用的触发器身份与等待结果；缺少必需参数时注册失败并说明缺项。 |
| AC-02 | Turn 完成触发器只在指定目标 Turn 完成后唤醒指定接收会话；不同会话或不同 Turn 的完成不触发它。 |
| AC-03 | step 阈值触发器在累计计数首次达到或超过阈值时唤醒一次；后续 step 不产生第二条唤醒。 |
| AC-04 | 进程正常退出和异常退出均触发一次，并将可获得的退出状态交给接收会话。 |
| AC-05 | 符合过滤条件的 IM 消息触发唤醒并传递正文与必要上下文；不符合条件的消息不唤醒。 |
| AC-06 | 指定时间到达后触发一次；相邻的其他时间点不触发。 |
| AC-07 | step 阈值异步触发器命中后，目标会话继续执行；同步触发器命中后，目标会话在检查点暂停，接收会话完成处理前不会继续执行。其他四类事件均异步通知且不暂停来源对象。 |
| AC-08 | 接收会话正在运行时，唤醒消息排在其当前 Turn 之后；step 阈值同步模式下，目标会话在排队和处理期间保持暂停。 |
| AC-09 | 应用重启后，未触发触发器仍处于等待状态；同步等待中的目标会话不会静默继续或永久挂起；事件最多造成一次唤醒。 |
| AC-10 | 取消成功后再发生匹配事件不产生唤醒；命中与取消并发时最终状态唯一且无重复消息。同步等待的取消或超时按已登记规则使目标会话进入明确终态。 |
| AC-11 | 不存在、不可访问或已结束的目标对象不能被报告为成功注册；运行中失效时触发器进入可查询终态。 |
| AC-12 | 查询触发器状态只返回当前 Agent 有权查看的注册，不泄露无关会话数据。 |

### 9. 场景与失败边界

| 场景 | 需求行为 |
|---|---|
| 同一条件短时间内重复出现 | 只接受一次命中，只排队一条唤醒 |
| 目标会话在等待期间被删除或不可用 | 触发器进入失败终态，注册会话可查到原因；不得转投到名称相似的其他会话 |
| 事件发生时接收会话正忙 | 保留唤醒，等待当前 Turn 结束；不丢弃、不打断 |
| 应用关闭时触发器仍等待 | 持久保留定义；重启后继续监听 |
| 应用离线期间发生时间事件 | 重启后检测到该绝对时间已到时，按一次性事件唤醒一次；过期策略不得默默丢弃 |
| IM 来源断连或重复投递 | 断连状态可判定；恢复后同一条消息最多产生一次唤醒 |
| 进程结果含大量输出或敏感信息 | 唤醒信息应提供处理结果所需内容；敏感信息仍遵守产品既有脱敏与访问约束，不以触发器扩大可见范围 |
| 注册会话与接收会话不同 | 触发消息只进入注册时明确指定的接收会话，且可追溯发起注册的会话 |

### 10. 成功指标

| 指标 | 事件与分母 | 目标 |
|---|---|---|
| 事件唤醒投递率 | 可确认已命中的触发事件数为分母；成功进入指定会话队列的事件数为分子 | ≥ 99%（不含目标会话永久不可用的事件） |
| 重复唤醒率 | 所有已命中的一次性触发器数为分母；同一触发器产生多条唤醒的数量为分子 | 0% |
| 重启恢复率 | 重启时仍有效且未触发的触发器数为分母；重启后恢复等待或按已发生事件正确命中的数量为分子 | 100% |

上述指标阈值为本需求的验收目标；采集口径不得记录消息正文、密钥或不必要的个人信息。

### 12. 开放决策与假设

以下内容不改变本次已确认的用户可见主行为，但需在技术方案或实现前闭合；不得由实现者自行改变本需求的五类触发场景、step 阈值同步/异步取值、其他事件异步通知、一次性语义、排队语义或重启恢复承诺：

| 项 | 当前要求 | 关闭节点与条件 |
|---|---|---|
| step 的精确定义与计数来源 | 产品上是目标 Agent 执行进度的一步；各类工具调用或模型循环如何归为一步属于实施契约 | 技术方案评审前明确计数口径，并验证阈值行为可观测 |
| 同步处理的完成与等待边界 | step 阈值同步模式中目标会话暂停至接收会话完成唤醒处理；超时、接收会话失败、用户取消及应用退出时必须有明确终态，不能让目标会话无限期挂起或未经说明继续 | 技术方案评审前定义完成信号、可配置的超时/取消行为、重启恢复方式；相关行为列入验收 |
| Turn 事件身份 | 用户可指定一个当前 Turn；不存在或已经终结时注册失败 | 技术方案评审前明确用户可见的选择与错误行为 |
| IM 消息匹配规则 | 注册需限定来源消息流，并支持必要过滤；不能全局隐式监听 | 技术方案评审前明确首期可选范围及拒绝模糊订阅的行为 |
| 定时精度与过期窗口 | 绝对时间到达后只唤醒一次；离线期间到期的项重启后需处理 | 技术方案评审前明确可接受延迟与过期保留时长 |
| 失败重试与终态 | 暂时不可用时保留并重试；永久失败可查询 | 技术方案评审前确定用户可见的重试终止条件与失败说明 |
| 触发器总量与期限上限 | 本文不向 Agent 暴露可无限积累且不可管理的承诺 | 实现启动前确定容量与过期规则，保证注册超限有明确失败结果 |

### 13. 业务词与内部词

| 业务词 | 内部含义（下钻用） |
|---|---|
| 唤醒消息 | runtime 投递到会话队列、使 Agent 获得处理机会的事件消息 |
| step | 用于表达 Agent 执行进度的产品计数单位，精确定义待技术方案验证 |
| 触发器 | Agent 注册的一次性事件等待请求 |
