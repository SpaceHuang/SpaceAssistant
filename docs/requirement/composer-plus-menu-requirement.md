# 输入框加号菜单与目录上下文授权 — 需求规格

**版本：** 1.0
**日期：** 2026-10-03
**状态：** 待评审
**关联文档：** [引用的文件](./referenced-files-requirement.md)、[多工作目录](./multi-workdir-requirement.md)、[工作目录边界与沙箱策略分层](./session-d961cc51-workdir-boundary-and-sandbox-policy-layering-requirement.md)、[上下文用量估算](./context-usage-estimated-occupancy-requirement.md)

## 1. 概述

### 1.1 背景

输入框当前的「+」按钮直接打开图片选择器，仅能添加图片视觉输入。用户还需要从同一处显式选择目录，向 Agent 提供工作目录之外的上下文并申请访问许可；同时，希望能手动触发当前会话上下文压缩。

### 1.2 目标

| ID | 目标 |
|---|---|
| G1 | 点击「+」后通过清晰菜单访问图片、目录和压缩三项功能。 |
| G2 | 图片选择能力及既有附件发送行为保持可用。 |
| G3 | 用户选择的目录成为当前会话可识别、可撤销、可审计的额外访问范围，支持超出当前工作目录的路径。 |
| G4 | 用户可主动触发当前会话上下文压缩，并看到运行结果。 |

### 1.3 非目标

- 不把目录选择等同于将其注册为全局工作目录，不切换当前工作目录或会话数据归属。
- 不因选择目录而绕过敏感路径、系统目录、符号链接检查、工具调用审批或其他既有安全规则。
- 不在本需求中改变自动压缩策略、压缩算法、模型路由或上下文预算口径。
- 不将目录内文件自动上传或立即全部读入对话；目录作为 Agent 后续工具访问的上下文范围。

## 2. 现状与约束

- `MessageInput` 中的加号当前直接触发隐藏图片文件输入；图片附件在发送消息时作为视觉输入处理。
- 项目已有 Electron `dialog:select-directory` 目录选择 IPC，可复用原生目录选择体验；该能力本身不构成 Agent 文件访问授权。
- 安全策略以工作目录边界、路径事实和工具执行许可判定访问。当前“用户明确选择工作目录之外目录”的意图尚需接入该策略链路，不能只在 Renderer 保存一条路径后就认为授权成功。
- 项目已有上下文压缩规划、事件持久化和压缩标记能力；本需求要求入口触发现有用户主动压缩语义（`user_compact`），具体执行链路应复用项目已有压缩机制。

## 3. 功能需求

### 3.1 加号菜单

点击输入框「+」按钮打开菜单，包含以下三项，顺序固定：

1. **选择图片**：打开既有图片文件选择器，结果进入现有图片附件区。
2. **选择目录**：打开原生目录选择器，成功后将目录加入当前会话的额外上下文目录列表。
3. **压缩上下文**：触发当前会话的用户主动上下文压缩。

交互要求：

- 菜单锚定加号按钮，打开后可通过点击外部、按 `Escape` 或选择菜单项关闭。
- 菜单项具备可访问名称、键盘焦点和明确 hover/focus 状态。
- 图片项保留现有“过多图片”提示和附件数量上限行为。
- 无当前会话、会话正处于不允许操作的状态或压缩不可执行时，应按对应操作禁用菜单项并说明原因；不得因此禁用仍可安全使用的其他菜单项。
- 操作失败时显示可理解的错误提示；取消目录/图片选择不视为错误。

### 3.2 选择图片

- 菜单项选择后打开现有图片选择器，允许的格式、数量限制、预览、移除、暂存和发送逻辑保持一致。
- 取消选择不改变已添加附件。
- 若已有附件达到上限，图片菜单项显示/提供现有上限提示，不打开选择器。

### 3.3 选择目录及授权

#### 3.3.1 目录选择与状态

- 通过主进程原生目录选择器选择一个现存目录；用户取消则无状态变化。
- 选择后在输入框附近显示目录上下文条目，至少展示可辨识的目录名称；完整路径可通过 tooltip/详情查看，避免窄布局溢出。
- 当前会话可添加多个目录。规范化后的同一路径重复选择应去重，不新增重复授权。
- 用户可逐项移除目录。移除后该目录不再作为后续 Agent 调用的授权范围；已完成操作和历史消息不回滚。
- 目录列表随会话切换正确加载/清空，不泄漏到其他会话；是否跨应用重启持久化由会话状态持久化实现，产品语义要求重启后仍可恢复同一会话的授权列表。

#### 3.3.2 授权边界

- 用户选择目录表示用户明确要求 Agent 在当前会话中将该目录纳入可访问上下文，适用于当前工作目录之外的路径。
- 授权必须由主进程建立并校验，绑定当前会话及规范化/真实路径；Renderer 传入的目录字符串不能单独作为授权凭据。
- 访问判定必须识别目录授权范围，并仅覆盖该目录自身及其后代路径；路径前缀相似但不属于后代的目录不得匹配。
- 读取、列举、搜索等工具仅在授权目录范围内按既有策略执行。写入/执行仍需遵循原有工具审批、危险操作确认及策略规则；目录选择不默认为所有操作免确认。
- 对选择目录内的符号链接，授权不得自动扩展到链接目标的范围之外；目标路径仍须经过现有真实路径及敏感路径判定。
- 系统目录、应用数据/凭据敏感目录及既有明确禁止访问范围仍然拒绝；若目录无法安全授权，应告知原因且不得记录为已授权。
- 权限范围只限当前桌面会话，不自动授予飞书/远程入口、其他会话、计划任务或后台任务。
- 安全决策和审计记录需能区分“工作目录内”与“用户选定目录授权”，并关联会话和授权目录标识；日志中避免记录不必要的敏感文件内容。

#### 3.3.3 Agent 使用目录

- 被选目录应进入当前会话的工具上下文，使 Agent 能据此构造可访问路径和说明其来源。
- 用户只授权目录范围，不等同于要求立即扫描全部内容。Agent 按任务需要读取具体内容，并受工具既有范围、大小及确认规则约束。
- 超出当前工作目录且不在已选目录内的路径继续按既有边界规则拒绝或进入既有确认流程，不得因本次选择而扩大到父目录、兄弟目录或整个磁盘。
- Agent 不得将目录选择陈述为用户已授权具体破坏性操作；用户后续提出的具体任务仍按操作风险走现有安全决策。

### 3.4 压缩上下文

- 选择「压缩上下文」后，以当前会话最新的可压缩上下文触发一次用户主动压缩（reason=`user_compact`），复用已有摘要/压缩、提交和事件回放机制。
- 该操作不发送新的用户消息，不调用工具，不启动新一轮 Agent 任务。
- 正在生成、等待审批或执行中的会话不得并发压缩；菜单项禁用并给出状态说明。压缩期间显示进行中状态，防止重复触发。
- 压缩仅在结果通过现有提交校验后生效；失败时保留压缩前有效上下文，并提示失败原因/可重试状态，不留下半提交状态。
- 无可压缩内容或压缩未减少上下文时，给出“无需压缩/没有可压缩内容”反馈，不误报成功。
- 成功后更新消息投影、上下文用量/投影和现有压缩标记；历史消息仍可查看，压缩后的上下文遵循现有 replay 语义。

## 4. 状态与交互建议

```text
+ 按钮
  └─ 菜单
      ├─ 选择图片 → 原生文件选择 → 附件暂存 → 发送时作为视觉输入
      ├─ 选择目录 → 原生目录选择 → 主进程校验并建立会话范围 → 显示可移除目录条目
      └─ 压缩上下文 → 检查会话状态 → user_compact → 提交/反馈
```

菜单应采用本项目现有菜单/Popover 视觉规范。目录条目与图片附件在视觉上区分，避免用户误以为目录内容已经上传。

## 5. 验收标准

| ID | 验收条件 |
|---|---|
| AC1 | 点击「+」展示三项菜单；键盘可访问，外部点击和 Escape 可关闭。 |
| AC2 | 选择图片仍走原图片流程，附件预览、移除、数量上限及发送行为不回归。 |
| AC3 | 用户可选择工作目录之外的目录，取消选择无副作用，重复路径去重，条目可移除。 |
| AC4 | 选定目录仅对当前会话生效；切换会话后不串用，恢复原会话时列表与授权一致。 |
| AC5 | Agent 可在选定目录范围内按工具策略访问；目录外、兄弟路径、边界前缀伪匹配和越界符号链接均不能借此授权。 |
| AC6 | 选目录不绕过系统/敏感路径规则、写入确认及既有安全策略；拒绝时 UI 明确说明且无授权残留。 |
| AC7 | 远程会话、其他会话及后台任务不能消费该桌面会话的目录授权。 |
| AC8 | 压缩菜单项触发一次当前会话 `user_compact`，不发送消息、不调用工具；进行中防重入。 |
| AC9 | 成功、无需压缩、不可压缩、失败四种结果均有准确反馈；失败不破坏既有上下文。 |
| AC10 | 压缩成功后现有压缩标记、上下文投影及会话恢复/replay 保持一致。 |

## 6. 待实施设计关注点

1. 明确目录授权的持久化实体与撤销时机，并复用统一安全策略入口，而非新增绕过策略的快捷通道。
2. 明确目录范围如何传入文件类工具的路径分类、事实探测、许可构造和执行校验，避免只在 prompt 中告知模型。
3. 明确用户主动压缩的 Renderer 到 Runtime 触发接口，并确保事务状态与现有事件流一致。
4. 补齐中英文菜单、目录状态、失败提示的 i18n 文案。
