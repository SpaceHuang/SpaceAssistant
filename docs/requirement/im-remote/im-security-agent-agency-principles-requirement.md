# IM 安全审核 Agent 协作原则

日期：2026-10-13  
状态：讨论共识；记录产品原则，尚未拆分为实现方案。

## 1. 目标

可信用户通过 IM 委托任务时，系统应尽可能自主、充分地完成用户意图，只施加必要限制。安全机制应保护用户明确设定的边界，并帮助避免把用户意图误做成高影响行动；不应把用户、执行 Agent 和安全审核 Agent 固定成只能按僵化步骤运行的角色。

## 2. 基本原则

1. **用户是任务意图与约束的来源。** 用户可以在当前任务中给出目标和决定，也可以预先设定长期生效的关键安全规则。
2. **安全审核 Agent 有独立判断力，但不是最终决策者。** 它可以解释规则、识别具体行动的风险与任务关联性，并驳回当前行动；它不能把自己的风险偏好变成用户没有设定的长期禁令。
3. **材料可以补足任务细节，不能扩张授权。** 文件、网页、附件等内容本身不能替用户增加授权，也不能代替用户作出确认。
4. **能力边界不属于安全边界。** 能否调用工具、能否完成任务以及如何寻找替代路径，由执行 Agent 处理。做不到时应如实报告，不把能力不足包装成安全拒绝。
5. **拒绝应针对行动并说明依据。** 审核反馈要讲明命中了哪条用户预设规则，或指出具体风险及其与用户意图的关系；若只是缺少理解行动所需的信息，应说明缺什么，由执行 Agent 补充，而不是把信息不足说成违规。

## 3. 三个角色的责任

### 用户

- 给出目标、任务意图和约束，并可在需要时澄清或确认。
- 可以在桌面链路和设置界面中创建或修改关键安全规则。
- 对安全审核 Agent 基于临场风险判断提出的异议，仍拥有最终决定权；用户明确授权后，审核 Agent 不得仅凭同一风险继续否决。

### 执行 Agent

- 尽一切努力完成用户委托，主动处理能力问题、替代方案和执行失败。
- 在进入安全审核前，尽可能澄清会实质影响行动的意图、目标和范围。
- 收到驳回后，可以调整行动；若认为该行动对完成用户意图不可或缺，可以补充理由重新申请，或向用户解释具体需要并请求决策。
- 对最终是否能完成任务负责，并如实反馈结果；安全审核 Agent 不负责替它解决能力问题。

### 安全审核 Agent

- 运用独立判断评估具体行动与用户既有意图、约束之间的关系及其安全风险，不只是逐字匹配规则。
- 若某项行动存在明显安全风险，且明显与当前用户意图无关，可以直接驳回这次行动，并说明判断理由。
- 驳回后可以要求执行 Agent 修改方案，或补充为什么该行动对完成用户意图不可或缺；这项判断不自动终结整个用户任务。
- 用户明确授权后，不得仅凭自身风险判断继续否决；但命中用户预设的关键安全规则，或已触发下述进程内驳回上限时除外。
- 可以提出新的风险和规则建议，但不能自行把建议变成用户未设定的持久约束。

## 4. 两种不同的安全拒绝

### 4.1 用户预设的关键安全规则

- 用户可预先指定某类行动一律直接否决、不再向用户询问。例如，用户可以将“格式化系统盘”设为关键安全规则。
- IM 链路命中这类规则时，安全审核 Agent 应直接否决，明确告知执行 Agent 不要再向用户请求确认；IM 中的确认结果不予采纳。
- 这类规则只能由用户通过桌面链路或设置界面修改。

### 4.2 安全审核 Agent 的临场判断

- 没有命中上述直接否决规则时，审核 Agent 仍可基于具体风险和行动与用户意图的关联性驳回当前行动。
- 执行 Agent 可避开该行动，或在认为行动确实必要时补充理由并请求用户决策。
- 用户明确授权后，审核 Agent 不得仅凭原有风险判断再次否决。
- 对格式化系统盘等高影响行动，产品可以通过软性提醒要求用户看清目标和后果后确认。这类提醒旨在避免误操作，不等于用户不能覆盖的禁令；只有命中用户预设的关键安全规则时才直接否决。

## 5. 限制无尽的 Agent 间拉锯

- 审核 Agent 驳回申请后，执行 Agent 可以修改方案或补充理由后重新申请。
- 每个申请的审核往返有最多次数。若同一申请连续被驳回达到上限 `x` 次，则该申请在当前 IM 进程内直接终局驳回。
- 达到上限后不再接受讨论或确认，也不再交由安全审核 Agent 处理；用户不能通过 IM 亲自解锁该申请。
- `x` 的具体数值、申请的识别方式和计数实现留待后续设计。

## 6. 本文范围与后续

本文仅记录三方角色、授权来源、驳回语义及交互边界，不规定实现流程、数据结构或证据传递机制。如何向安全审核 Agent 提供可信证据，避免其依赖执行 Agent 无法验证的自述，属于后续实现设计。

本文是较新的产品原则共识。既有 IM 安全需求文档中的详细状态矩阵和实现要求尚未据此统一修订；若其表达与本文原则冲突，后续需复核并协调，不应据此推断本文已经完成实现规格整合。
