# IM 助理 Agent 与执行 Agent 协同需求（草案）

日期：2026-11-02  
状态：需求草案；D-01 至 D-07 的产品决策均已确认。不代表当前链路已具备助理协调行为。

## 第 0 层：决策摘要【人必读】

**一句话：** 用户通过 IM 委托任务后，由统一助理 Agent 吸收执行过程中的沟通细节，协调执行 Agent，并尽量把必须由用户回答的问题合并成清楚、友善的一批问题。

**为什么做：** IM 是异步沟通方式。用户发出指令后通常不会守着聊天窗口，耐心回答执行过程中的每个疑问。零散打断增加用户回来处理的次数；技术化、上下文不足的问题也增加理解成本。不改进时，用户仍需承担任务拆分、解释执行细节和逐项响应的工作。

**预期收益：** 减少用户被打断和处理执行细节的次数，降低决策说明的理解成本，并让任务在用户离线期间尽可能继续推进。

**本期范围：** 仅调整 IM 链路；桌面聊天保持现状，不接入本需求的助理协调流程。

**架构约束：** 优先用定制提示词、Skill 等软能力实现沟通、汇总和协调。避免为本需求把通用 Agent SDK 或 Runtime 扩展成专用多 Agent 工作流引擎；只有可靠性、安全性或可验收性无法由软能力保证时，才增加必要硬逻辑。

| D-02 | 决策问题收集与忙碌处理 | 已确认；具体收集、排队和紧急交接规则见下文“D-02：决策问题的收集、排队和处理”。 |

## 第 1 层：用户行为需求【人机共读】

### 角色责任

| 角色 | 责任 |
|---|---|
| IM 助理 Agent | 理解用户请求、协调任务拆分和执行、批量处理执行 Agent 的待办、汇总用户决策、用易懂语言沟通进度与结果。 |
| 执行 Agent | 专注执行具体任务；向助理提交进度、信息需求、待用户决策事项、结果或失败原因；不直接向用户发消息。 |
| 安全与授权机制 | 独立校验身份、策略、具体操作和授权有效性。助理不能代替用户批准必须由用户批准的动作。 |
| 渠道适配器 | 分别处理飞书、微信的平台收发和消息格式；向助理提供统一输入，并将助理输出送回发起任务的原渠道。 |

### 主流程

1. 用户通过微信或飞书提交任务；系统先按既有规则完成身份与准入检查。
2. 助理理解请求。目标足够清楚时直接分派；只有实质影响目标、范围或结果的歧义才向用户提问。
3. 多个执行 Agent 可并行工作。助理及时分派明确任务，并在执行 Agent 运行期间响应其提交的询问或事项。
4. 执行 Agent 将进度、问题、行动请求和结果交回助理。助理一次可以处理多条待办，不要求一条待办对应一个独立助理 turn。
5. 助理先利用已有任务上下文、材料或系统可查事实处理问题；确实需要用户决定时，尽量合并为一批，用用户易懂的表达说明问题、选项及影响。
6. 用户可用简短自然语言回答一项或多项，也可只回答部分。助理把明确回答映射到相应事项；未回答或无法确定对应关系的部分继续等待或针对性追问，不推断为批准。
7. 助理汇总相关结果，通过原 IM 渠道告知用户。失败、部分完成和等待状态必须如实表达。

### D-02：决策问题的收集、排队和处理

- **普通问题收集：** 从首个普通待决问题进入收集批次起，最多收集 5 分钟或最多合并 5 项，任一上限先到即封批。若当前所有可继续的执行任务都被待决问题阻塞，则提前封批。
- **收集窗口不等于响应时限：** 5 分钟只决定何时停止收集并封批，不承诺助理必须在 5 分钟内完成分析或把消息送达用户。
- **助理忙碌时：** 封批事项进入待处理队列，不强制中断正在进行的助理 turn。当前工作到达可安全交接点后，优先处理紧急事项，再处理已封批的普通决策事项，之后处理可延后的进度汇报。
- **紧急问题：** 若延迟询问会导致任务无法及时继续，或决定将在 5 分钟内过期/错过有效时机，该问题立即进入高优先级队列，不等普通收集窗口，也不等普通问题凑批。助理忙时，在当前工作可安全交接后优先处理；不要求中断正在进行的模型调用、工具调用或已提交操作。高优先级代表排队顺序，不承诺在截止前完成处理或送达；若当前操作尚不可安全交接，需等它结束或到达安全交接点。
- **批次边界：** 达到上限后到达的问题进入下一批；助理处理期间到达的新事项不得遗漏或重复。普通进度可以合并，不把每个内部事件都转成单独通知。

### D-04：执行 Agent 请求类型与助理处理规则（已确认）

下表是已确认的产品规则，不授予助理安全权限。用户必须授权的动作仍由现有安全与授权机制决定。

| 请求类型 | 示例 | 助理行为 | 是否询问用户 |
|---|---|---|---|
| 任务上下文已包含的信息 | 目标文件、项目名称、用户刚说明的偏好 | 从任务上下文提取并转交，避免重复询问；材料可补足事实，不能扩张授权。 | 否；确实缺失时按用户信息缺失处理。 |
| 系统可查明的事实 | 工作区结构、已有文件、工具状态、公开资料 | 让执行 Agent 或工具先查证，再继续。 | 否。 |
| 不改变目标的可逆实现细节 | 等价格式、命名或组织方式 | 在任务目标和既有约定内选择合理方案，结果中简要说明。 | 通常否；超范围或代价显著时询问。 |
| 目标、范围、优先级或偏好实质歧义 | 不同解释会产出不同结果；多个任务的时间/质量优先级冲突 | 合并同类问题，简要解释选项差异；不能把猜测当作用户偏好。 | 是，除非上下文足以消歧。 |
| 用户专属信息缺失 | 私人账号选择、业务背景、用户未给出的决策标准 | 先查现有上下文，仍缺失且影响结果时提出简短问题。 | 是。 |
| 安全授权或对外影响 | 删除/覆盖、对外发送、权限变更、策略要求人工批准的调用 | 可解释和整理请求；不能自行批准、扩大授权或把多项操作包装成笼统同意。 | 按既有安全策略；助理不得代答。 |
| 执行 Agent 提出替代方案 | 原工具不可用；建议改变范围、数据来源或额外成本 | 在原目标与授权范围内协调替代；实质改变目标、数据范围、外部影响或成本时交用户决定。 | 视影响而定；授权仍走安全机制。 |
| 错误、阻塞或失败 | 工具失败、资源不可用、部分完成 | 先尝试范围内安全恢复；无可行路径或替代会改变用户预期时说明情况并问下一步。 | 可安全恢复且不改目标时否；否则是。 |
| 进度、结果或内部协作 | 阶段完成、一个 Agent 需要另一个 Agent 的输入 | 协调依赖并合并进度，不把内部协作噪声逐条转给用户。 | 否，除非同时涉及用户决定。 |

**统一规则：** 上下文已知、可查事实、可逆且不改变目标的细节、范围内安全恢复和内部协作由助理/执行链处理；实质目标或偏好不明、用户专属信息缺失、超范围替代由助理汇总询问；安全授权绝不由助理决定。

### 用户沟通要求

- 用普通、简洁的语言说明“需要决定什么、为什么、会有什么结果”，不直接转发难懂的执行细节。
- 为减少打扰不能隐去会改变用户决定的重要对象、范围或影响。

## 第 2 层：范围与验收【机｜人工可跳过】

### 本期做

- 微信和飞书由统一助理负责 IM 用户沟通与任务协调，各渠道保留平台适配。
- 助理可批量处理多条执行 Agent 事项，并合并需要用户回答的问题。
- 执行 Agent 可并行运行；助理能及时分派任务，并在执行期间响应 Agent 询问。
- 用户通过 IM 和助理对话查询任务状态、等待原因和结果，不新增独立任务管理面板。
- 保留现有身份、授权、策略、确认、审计和恢复边界。
- 优先用定制提示词和 Skill 等软能力，避免把通用 SDK/Runtime 改造成专用工作流引擎。

### 明确不做

- 不改变桌面聊天链路。
- 执行 Agent 不直接向用户发送消息或选择消息目的地。
- 助理不代替用户作出必须由用户作出的安全授权决定。
- 批量呈现不合并底层授权范围；未答不代表同意。
- 不建设通用多 Agent 工作流平台。

### 验收标准

| ID | 用户可见验收要求 |
|---|---|
| AC-01 | IM 后续澄清、决策请求、进度说明和结果由统一助理表达；执行 Agent 不直接给用户发消息。 |
| AC-02 | 助理可在一次协调处理中识别并处置多条待办，不要求一条事项启动一个独立助理 turn；事项均能对应回来源任务。 |
| AC-03 | 多项问题可合并呈现，但每项对象、影响和选项仍清楚，不混淆决定范围。 |
| AC-04 | 用户的自然语言回复可覆盖一项、多项或部分事项；仅明确匹配的答案生效，未回答或歧义部分不视为批准。 |
| AC-05 | 目标清楚时助理直接分派，不要求先确认常规拆分；只对实质影响目标、范围或结果的歧义提问。 |
| AC-06 | 多个执行 Agent 可并行；一个 Agent 未完成不得阻止其他明确任务的分派或其他 Agent 询问的处理。 |
| AC-07 | 执行 Agent 运行期间提交事项后，助理能被唤醒协调，无需等待该 Agent 的完整执行 turn 结束。 |
| AC-08 | 普通决策事项按 5 分钟/5 项上限封批；全体可继续任务都被阻塞时提前封批。5 分钟不承诺处理完成或送达。 |
| AC-09 | 紧急决策事项不等待普通收集窗口，进入高优先级队列；助理忙时在当前工作可安全交接后优先处理，不强制中断当前调用或已提交操作。 |
| AC-10 | 助理忙碌期间或应用重启/turn 中断后，已封批事项仍保留待处理；恢复后可继续处理，不能丢失、重复派发或重复发送。 |
| AC-11 | 用户可通过 IM 对话查询任务状态、等待原因和结果，本期无需独立任务管理面板。 |
| AC-12 | 桌面聊天继续现有行为，不进入本需求的 IM 助理协调流程。 |
| AC-13 | 助理或执行 Agent 的表达不能绕过既有授权检查；授权失效或不匹配时，不执行相应操作。 |
| AC-14 | 失败、部分完成或等待用户决定时，助理准确说明状态，不把未完成任务说成完成。 |

## 术语

| 术语 | 含义 |
|---|---|
| IM 助理 Agent | 代表系统与 IM 用户沟通、协调任务并汇总结果的 Agent。 |
| 执行 Agent | 接收明确任务并完成具体工作的 Agent；不直接与用户沟通。 |
| 待处理事项 | 执行 Agent 交给助理处理的进度、问题、决策请求、结果或失败信息。 |
| 协调批次 | 助理一次读取和处置的一组待处理事项；不意味着事项共享授权。 |
| 决策批次 | 助理集中呈现给用户的一组待回答问题；每项决定仍有独立作用范围。 |
