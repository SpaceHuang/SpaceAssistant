# 工作目录 AGENTS.md 指令支持需求

日期：2026-10-14  
状态：需求草案，供评审；本次仅输出需求，不实施代码改造。  
范围：SpaceAssistant 宿主的项目指令发现、装配与生效语义；保持 agent-sdk 的通用运行时架构。

## 1. 背景与目标

用户希望在当前工作目录放置 `AGENTS.md`，产品便能自动遵循其中的项目背景、开发命令、编码规范、测试要求与协作约定，无需逐轮粘贴，也无需复制为产品专有格式。

文件名统一为 **`AGENTS.md`**。不增加 `AGENT.md` 别名，不自动读取 `CLAUDE.md`、`GEMINI.md` 或其他产品的规则文件。

[AGENTS.md 官方约定](https://agents.md/)采用普通 Markdown，支持根目录与嵌套目录指令，针对目标文件以更近目录的规则为优先，显式用户要求可覆盖项目约定。本版本仅采用其标准文件名与根文件约定，不支持嵌套目录指令；各产品的全局目录、覆盖文件、扫描边界及预算策略并不完全相同，本文不承诺完整复刻某一产品。

目标：

1. 当前调用实际工作目录中的 `AGENTS.md` 自动生效，覆盖桌面、飞书、微信、自动化等使用本产品 Agent Runtime 的入口。
2. 明确来源、优先级、刷新时点、失败行为与上下文成本，避免“文件存在但不知是否生效”。
3. 与现有 `SPACEASSISTANT.md`、Skills 和用户指令共存，不改变工具权限与安全审批。
4. 发现与文件读取留在宿主；SDK 继续消费通用调用材料和端口，不识别产品文件名或 Electron 状态。

## 2. 交付与验收边界

本版本交付范围已确认：**仅自动加载当前工作目录根部的 `AGENTS.md`，不支持子目录指令**。实施与验收均以此为边界；发布说明必须明确该限制，不得宣传嵌套兼容。

| 范围 | 当前环境可自动验证 | 需要真机或外部系统验收 |
| --- | --- | --- |
| 发现、选择、预算、快照、路径边界、跨目录隔离 | 临时目录单测、伪 provider 请求捕获、宿主集成测试 | 无 |
| 各入口共用同一装配材料 | 模拟桌面 / IM / 自动化入口验证 | 真实飞书、微信消息往返 |
| 模型遵循开发规范 | 验证请求包含完整指令与优先级说明 | 真实模型行为抽查；文本注入不等于绝对服从保证 |
| 文件刷新与状态展示 | 模拟创建、删除、替换、权限错误及状态投影 | Windows / macOS / Linux 文件系统与桌面 UI 操作 |

本次交付为需求文档，版本范围已由用户确认。其余推荐默认值是评审基线，不代表用户已确认全部产品取舍。

## 3. 当前实现与差距

以下基于当前工作区静态检查，不将既有设计文档视为已实现事实。

| 现有位置 | 已有能力 / 约束 | 本需求的影响 |
| --- | --- | --- |

## 4. 功能需求

### FR-01 文件发现与作用域

- 在每个逻辑 provider 请求开始装配前，使用当时解析出的会话工作目录检查 `<effectiveWorkDir>/AGENTS.md`。排队任务在真正开始时解析目录，不能在入队时冻结全局活动目录。
- `effectiveWorkDir` 来自既有会话 / 调用工作目录解析结果，包含固定目录及远程会话绑定等现有规则；禁止使用 `process.cwd()` 代替。
- 本版本只检查这一处精确文件名，不向父目录搜索、不递归扫描、不读取用户主目录的全局规则。工作目录处于仓库子目录时，也只读取该工作目录文件；不会额外加载仓库根目录或任何子目录中的指令。
- 采用文件系统原生大小写语义，不额外枚举各种大小写别名；建议跨平台统一使用标准拼写。
- 普通 UTF-8 Markdown，无需 front matter 或必填标题；支持 BOM、CRLF 和中文。空文件或纯空白视为无有效指令。
- 不执行文件中的命令，不展开模板、环境变量或文件包含语法，不自动跟随 Markdown 链接及 `@文件` 引用。模型后续主动读取其他文件仍走原工具权限。
- 每个逻辑 provider 请求显式拿到自己的加载结果；同一 invocation 的后续逻辑请求可因文件或目录变化取得不同结果。缺失、禁用或失败均不能回退到其他工作目录或旧版本缓存。

### FR-02 注入与优先级

首次模型请求之前完成加载，以独立项目指令区块装配，包含来源相对路径、作用域及正文。包装必须把项目文本标为项目约定，避免把任意 Markdown 伪装为新的系统角色；正文按普通文本处理，不做模板求值。

语义优先级如下：

1. 产品和平台的强制规则、工具契约、安全边界及权限控制。
2. 当前用户明确要求；仅在不违反上一项的范围内覆盖项目约定。
3. 本次作用域内的 `AGENTS.md`。
4. `SPACEASSISTANT.md` 中与之冲突的项目约定。
5. 普通历史描述及自动推断的偏好。

Skills 是按需任务流程，不能因来源名获得更高权限；其内容与项目约定冲突时优先遵循当前用户明确指定的适用流程，仍受强制规则约束。无法同时满足且影响交付时，说明具体冲突再向用户澄清，不要求模型逐条报告无关差异。

现有 UI 语言提示须区分“界面默认语言”与强制工具约定，避免后置默认语言提示覆盖用户或项目明确的交流语言。

### FR-03 与现有项目记忆共存

- `AGENTS.md` 和 `SPACEASSISTANT.md` 可以同时加载，互不改名、不互相覆盖、不自动迁移。
- 前者定位为团队共享的行为约定，后者保留产品既有项目背景 / 记忆能力；不冲突的内容共同有效。
- 原 `projectMemoryEnabled` 保持只控制 `SPACEASSISTANT.md`；新增独立会话级 `AGENTS.md` 开关，默认开启，不把旧的“关闭项目记忆”解释为已经关闭新能力。
- 开关必须在会话中持久化；开关变更从下一次调用生效。状态查询不能泄露其他会话的路径或内容。
- 原项目记忆生成 / 保存功能仍仅操作 `SPACEASSISTANT.md`。未经用户明确要求，不自动生成或改写 `AGENTS.md`。

### FR-04 请求快照与刷新

- 每次新的逻辑 provider 请求边界都重新检查并读取当时目录中的当前版本，覆盖启动时缺失、运行中创建、原子替换、修改、删除等情况；不能仅靠文件 watcher 判断有效性。provider 层针对同一逻辑请求的网络 / 服务重试不算新边界。
- 每个 provider 请求使用其发出时解析到的工作目录与对应 `AGENTS.md` 快照。provider 请求在途期间，工作目录绑定若被外部改变，不追溯修改已发请求；响应返回后、任何工具派发前必须再次核对工作目录绑定。
- 若响应返回时发现绑定已变更，旧目录下的工具调用一律不得派发，避免用 A 的指令或授权在 B 执行。将其作为目录边界变化结果交回模型；下一次 provider 请求须读取新绑定目录的指令。已派发工具的副作用不自动回滚或重放。
- 保留 Agent 主动调用 `switch_work_dir` 的既有能力。切换成功即更新当前会话绑定；同一 invocation 的下一次 provider 请求使用新目录与新 `AGENTS.md` 快照，后续工具按现有动态 workDir 解析和新授权执行。宿主必须在请求边界刷新指令材料，并沿用 SDK 现有的通用上下文 / History 契约；不新增产品专用 SDK 接口，也不直接篡改循环内消息数组。不得在新目录操作中继续注入旧目录指令。
- `switch_work_dir` 在一批工具调用中构成顺序屏障：同批次其他调用不得并发越过它执行。切换成功后，未执行的同批调用作为未执行结果返回给模型，由模型在新目录指令上下文下重新决定是否调用；不得伪报成功、自动重放或丢弃调用结果。
- 审批等待期间若外部绑定发生变化，待审批操作按原目录授权失效处理，不得在新目录执行。恢复派发前重新校验目录与 grant；不匹配则取消该待派发操作、通知模型，并在下一 provider 请求加载新目录指令。若用户后来为新目录另行授权，须作为新操作重新发起。
- 同一逻辑 provider 请求的所有底层重试均复用该请求快照。该请求返回的工具调用及其审批等待期间的待派发操作，继续受产生它们的请求快照约束；若目录绑定与 grant 仍有效，审批通过后按原操作执行，不因文件内容更新而重解释已确认的工具参数。
- 上述工具完成、审批完成或普通工具运行结束后，若 invocation 发起下一次逻辑 provider 请求，必须重新读取当时磁盘版本。即使 invocation、目录和绑定均未变，期间文件内容变化也从这个新请求起生效。
- 因而，“恢复等待中的已有操作”沿用产生该操作的逻辑请求快照；“恢复后继续询问模型”属于新的逻辑请求，读取当前文件。若会话绑定已变化，则先按前述规则取消旧操作，再用新目录发起下一请求。
- 重启后只允许按已有历史能力只读查看已持久化的各逻辑请求指令快照，不恢复执行原 invocation。未完成模型请求、审批或工具派发仍按 SDK 既有语义标记为 `interrupted`，不得自动重放工具。
- 新 invocation 在重启后重新解析当前工作目录并加载当前磁盘版本。若某条历史请求的快照正文未持久化或不可读，历史界面明确显示“旧快照不可还原”；不得用当前文件冒充旧版本。快照正文如持久化，只能经既有受控历史 / 调用存储路径保存，日志不得记录正文。
- 跨 invocation 的旧项目指令不得作为当前有效规则反复累加。上下文压缩、历史重放后，当前 invocation 的有效指令须完整可用，且每个逻辑 provider 请求只注入其对应版本一次。
- 元数据至少记录来源、内容摘要、字节数、加载状态和加载时点。摘要仅用于定位版本，不能代替恢复所需正文。

### FR-05 预算与失败处理

建议首期单文件上限 **32 KiB（UTF-8 字节）**，项目指令 token 预算不超过 **min(8,000, 模型上下文窗口的 5%)**；使用现有 token 估算口径，预算针对正文和包装。数值是本产品建议，与既有项目记忆 40 KiB 限制相互独立。

| 情况 | 行为 |
| --- | --- |
| 不存在 / 空白 | 无有效区块，正常继续，不弹错误 |
| 开关关闭 | 不读取正文、不注入，状态为已禁用 |
| 超过字节或 token 上限 | 整份不注入，明确提示原因；禁止截断后宣称完整生效 |
| 权限不足、非法 UTF-8、非普通文件、越界链接 | 不注入，返回结构化失败原因；不复用旧缓存 |
| 读取中被替换或修改 | 有界重试一次；仍不稳定则本次不注入并提示 |
| 工作目录无效 | 复用原工作目录错误处理，不擅自回落其他目录 |

读取需有界：先判断文件类型和大小，并限制实际读取量，防止 stat 后文件增长导致无界读取。符号链接先解析真实目标，仅允许仍位于本工作目录授权边界内的普通文件；不得因项目文件获得新的目录 grant。检查与读取之间的竞态需纳入安全实现和测试。

“加载失败后继续”属于可见降级，必须在本轮状态中展示，并把“项目指令未加载及原因”作为宿主诊断材料告知模型，避免模型声称已遵循。用户可修复文件后让 invocation 发起下一逻辑 provider 请求以重新加载；不自动重跑已经产生副作用的工具。

### FR-06 状态与可观测性

- 在既有会话项目上下文 / 记忆相关入口提供独立状态：未发现、空文件、已禁用、已加载、加载失败。设置开关的变更从下一 invocation 生效；文件内容的变更从下一逻辑 provider 请求生效。不得用统一的“下一调用生效”提示混淆两个边界。
- 状态以 invocation 为分组，按逻辑 provider 请求记录目录、快照版本 / 摘要、读取状态与加载时点，并标明哪些待审批 / 待派发工具源自哪个请求。最新请求状态与历史请求状态可区分查看。
- 用户可查看指定请求实际采用的只读快照和加载原因；新版本不得覆盖旧请求历史。文件在旧请求之后发生变化时，显示“新版本将在下一次模型请求生效”，而非声称当前 invocation 全程使用单一快照。
- 无文件时不新增打断式提示；同一逻辑请求失败只提示一次。IM 至少支持文本说明降级，不要求照搬桌面面板。
- 日志只记录经过脱敏的关联标识、结果、摘要、大小与耗时，不记录正文、密钥或原始异常中的敏感路径。
- 新增文案遵循 i18n，错误经既有错误码模式投影；新增共享领域类型统一放宿主 `src/shared/domainTypes.ts`，避免两端重复定义。

## 5. 本版本不支持的范围

- 不自动发现、加载或合并子目录中的 `AGENTS.md`，也不实现按目标文件路径继承或覆盖规则。
- 工具访问子目录时，仍使用本次调用工作目录根部的指令快照，不因工具路径或 shell 的 `cd` 自动改变指令作用域。
- 不要求模型自行寻找子目录规则来补足自动加载能力。用户明确要求读取某个子目录文件时，可走普通文件工具读取，但不将其自动注册为项目指令。
- 不向工作目录上级搜索，不加载用户级全局指令，不支持 `AGENTS.override.md`、导入语法、专用规则编辑器或自动生成。
- 子目录支持若未来需要，另行提出需求并评审，不属于本版本的后续阶段、实施前置条件或验收项目。

## 6. agent-sdk 架构约束

职责链：**入口解析会话工作目录 → 宿主在逻辑 provider 请求边界发现与读取 → 宿主冻结该请求快照 → 统一提示装配 → SDK 通用请求 / 上下文 / History → provider**。文件版本可在同一 invocation 的不同逻辑请求间变化；SDK 不负责文件发现。

| 层 | 应负责 | 禁止事项 |
| --- | --- | --- |
| 宿主项目指令服务（建议新增 `electron/projectInstructions/`） | 路径校验、读取、预算、缓存隔离、状态与快照 | 借文件指令修改权限或业务审批 |
| 宿主调用准备与提示装配 | 按调用注入、统一优先级、恢复及用量计量接入 | 桌面 / IM 分别维护一套加载器；多处重复拼接正文 |
| `src/shared/` | 宿主 UI / IPC 共享状态类型与纯装配逻辑 | 引入宿主文件 IO 到通用 SDK 闭包 |
| `packages/agent-sdk` | 执行通用调用、维护上下文与历史契约 | 扫描 `AGENTS.md`、持有 watcher、读取 Electron 配置、依赖宿主 `src/shared` |
| provider 适配器 | 发送已经装配好的通用请求 | 根据 provider 各自读取项目文件 |

优先通过现有 system / 通用上下文材料传递结果，不新增 `loadAgentsMd` 一类产品专用 SDK 端口。确需补充可复用契约时，先证明既有入口不足，定义可序列化、中立语义及兼容性，再评审修改；不得通过 `any`、动态导入或 `additionalContext` 暗藏文件系统句柄绕过边界。

实际请求的 token 占用需覆盖新增指令，不能只在 UI 估算或只在首轮统计。SDK 入口闭包、依赖闭包和打包闭包门禁必须保持通过。不得为本需求另造 Agent 主循环、独立 provider 路由或第二套历史存储。

## 7. 权限与信任

项目指令是可由仓库贡献者修改的行为约定，不是用户授权凭据。诸如“关闭确认”“允许访问任意目录”“打印 API Key”等内容不得改变现有工具策略、授权范围、日志脱敏和远程审批规则。

本期遵循既有工作目录访问 / 信任机制，不引入新的首次逐文件确认。自动加载仅发生于用户已选择且调用获准访问的目录；不从网页、消息附件、引用链接自动提升出项目规则。读取和执行必须区分：读取规范不代表自动执行其中每条命令，具体动作仍由任务相关性和原权限机制决定。

## 8. 验收用例

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| A01 | 根目录含标准文件 | 首次及后续新调用请求包含带来源的完整正文且仅一份 |
| A02 | 仅有 `AGENT.md` 或其他产品规则文件 | 不自动加载 |
| A03 | 文件缺失、空白、BOM、CRLF、中文 | 缺失 / 空白无区块，其余正确解码 |
| A04 | 根指令、项目记忆与用户要求有冲突 | 请求含明确优先级；真实模型抽查对应行为 |
| A05 | 两目录并发，会话目录与活动目录不同 | 每次只注入本调用解析目录的内容，无串用 |
| A06 | 入队后切换活动目录 | 启动时按任务会话绑定解析，不取全局目录内容 |
| A07a | 文件缺失、修改、删除或原子替换发生在逻辑请求 R1 后、普通工具执行期间 | R1 请求和工具保持 R1 快照；下一逻辑请求 R2 反映文件新状态 |
| A07b | 文件在同一逻辑请求的 provider 重试期间变化 | 所有重试尝试继续使用 R1 原快照；后续逻辑请求 R2 加载新版本 |
| A07c | 文件在审批等待期间变化，目录与授权绑定不变 | 已待批操作按发起请求 R1 的快照 / 参数继续；审批完成后的新逻辑请求 R2 重新加载当前版本 |
| A08 | 同 invocation 等待恢复，绑定未变化 | 等待中的原操作沿用来源请求快照；恢复后发起的新 provider 请求重新读取当前文件，状态按请求分别保留 |
| A09a | 旧调用快照已持久化，修改或删除文件后重启并查看历史 | 只读展示该历史请求所用旧快照；不表示可以继续执行 invocation |
| A09b | 重启后创建新调用 | 重新解析当前工作目录并加载当前版本，旧规则不累加 |
| A09c | 旧快照正文缺失或不可读 | 明确显示旧快照不可还原，不以当前文件冒充 |
| A09d | 重启时存在未完成模型请求、审批或工具派发 | 仍为 `interrupted`，不自动恢复执行或重放工具 |
| A10 | Agent 主动切换 A→B，随后继续调用工具 | 切换成功后同批其他工具不越过屏障；下一 provider 请求注入 B 指令，后续工具按 B 的目录与授权执行 |
| A11 | `switch_work_dir` 与其他工具同批，切换失败 | sibling 不越过屏障；保留 A 绑定，并将未执行调用及切换失败交回模型处理 |
| A12 | provider 响应在途时外部切换 A→B | 旧请求可完成；其返回的旧目录工具调用不得派发；下一 provider 请求加载 B 指令 |
| A13 | 审批等待期间外部切换 A→B | 旧目录待审批操作不在 B 执行；校验并取消旧派发，通知模型在 B 下重新决策 |
| A14 | 关闭 AGENTS 开关 / 关闭旧记忆开关 | 分别只影响对应能力，开关变更从下一 invocation 生效，跨重启保留 |
| A15 | 某次新逻辑请求超限、读失败、文件不稳定 | 该请求整份不加载、有原因，不静默截断或回退旧版本；历史请求状态不被覆盖 |
| A16 | 普通目录、越界链接、文件增长及读取竞态 | 不挂起、不无界读取、不突破路径边界 |
| A17 | 正文含模板、标签、角色伪装及授权指令 | 不执行模板，不改变工具权限，日志无正文 |
| A18 | 桌面 / 飞书 / 微信 / 自动化 | 同目录与配置下加载语义一致，失败均可见 |
| A19 | 关闭 / 无文件的既有会话与 SDK 最小宿主 | 原有执行可用，SDK 无文件系统 / Electron 新依赖 |

自动测试以捕获真实装配后的 provider 请求为依据，不能只断言 loader 返回字符串。涉及文件刷新的测试应在普通工具、provider 重试、审批等待阶段分别修改文件，并验证原请求、待派发操作、后续请求及状态历史采用的版本一致；另覆盖目录切换和读取失败。

## 9. 实施建议与完成标准

### 本版本实施范围：根文件能力

建议顺序：宿主指令解析器与隔离快照 → 统一调用接入、动态目录切换屏障与历史只读展示 → 开关 / 状态及各入口降级提示 → 定向集成验证。具体签名先检查现有调用方再确定，不把本需求中的建议模块名当成必须新增的公共 API。

完成标准：A01–A19 自动验证覆盖相应确定性行为；真实模型、真实 IM 与三平台操作结果分别记录，不将模拟验证写成真机通过。产品说明公开首期作用域边界。

### 验证纪律

- 开发期间合并运行相关定向测试；接口变化才跑相应类型检查，文案变化跑 i18n 类型生成和校验。
- 每阶段至多一次主进程增量构建；涉及渲染进程时补充渲染类型检查。
- 架构验收执行 `npm run check:agent-sdk`；按仓库要求在阶段收尾 / 提交前执行全量测试，最终验收执行完整构建。
- 实施阶段按仓库纪律分别评审并提交；本次文档工作不修改运行时代码、不执行构建，也不包含其他工作区改动。

## 10. 决策汇总与待评审项

| 决策 | 推荐基线 | 原因 |
| --- | --- | --- |
| 本版本范围（用户已确认） | 仅工作目录根文件，不支持子目录 | 子目录发现、继承、覆盖与对应验收均不纳入本版本 |
| 既有记忆共存 | 独立开关，冲突时 AGENTS 优先 | 避免破坏旧功能，同时为通用项目规范确定地位 |
| 超限处理 | 32 KiB + token 预算，整份跳过并提示 | 避免截断关键约束后误报生效 |
| 新逻辑请求读失败 | 可见降级继续，不复用旧内容；保留此前请求的历史状态 | 明确本请求未采用项目指令，不混淆同一 invocation 的旧结果 |
| 文件内容刷新 | 同一 invocation 的新逻辑 provider 请求读取当前文件；同一请求重试及其待派发操作保留来源快照 | 确保恢复行为与刷新边界一致 |
| Agent 主动切换目录 | 切换成功后保留同一 invocation；下一 provider 请求加载新目录指令，同批次工具受屏障约束 | 兼容既有 `switch_work_dir`，避免新旧目录规则与授权错配 |
| 外部切换或审批期间切换 | 旧目录待派发工具失效；重新校验后在新目录下请求模型重新决策 | 避免旧目录操作跨界执行 |
| 请求重试与等待恢复 | 同一逻辑请求的尝试及其待派发操作沿用来源快照；后续逻辑请求重新读取文件 | 分清请求级材料一致性与 invocation 生命周期 |
| 重启恢复 | 只读历史快照；未完成 invocation 维持 `interrupted`；新调用读取当前版本 | 明确历史还原不等于可执行恢复 |

除已确认的版本范围外，其余推荐项可在需求评审时调整，但必须同步更新测试断言与发布说明，不能由不同入口自行选择行为。
