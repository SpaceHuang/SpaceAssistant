## 已实现

- toolkit gate 的真实 `PolicyDecision`（decision ID、rule IDs、依赖指纹、策略修订）与 permit authorization generation、当前 process generation 只在明确的 session-message toolkit invocation 上放入 host execution context。
- `RegisteredAgentTurnTools` 将 gate metadata 保存在 prepared execution context，confirmation receipt/answerer 仍来自 host preparation stage；刷新上下文/重规划时保留这些 safety-owned 字段。
- send handler 将 host gate authorization 交给 session message service。接纳时一次性保存原始 authorization binding（决策/receipt 引用、owner/target、target generation、desktop scope、payload digest、policy revision 和代次）；接纳后以 CAS 保存 execution approval。
- approval service 要求真实用户 receipt、`toolkit-act-ask`、真实 decision trace/依赖指纹与代次，且 owner、target、request 均匹配且仍 queued；agent answerer、错误身份/目标和其他 rule 均拒绝。
- desktop queue entry 暴露由持久分类得出的 source；普通 outbound drainer 对 `agent-session` 明确拒绝、保留队列并审计，不会将它当作普通用户输入执行。
