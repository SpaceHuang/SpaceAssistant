# A01 可信发送与撤回事实服务

## RED / GREEN

- RED：`action.session.message` 用例首次运行，目标删除后对同一发送请求重放失败（`SESSION_MESSAGE_TARGET_UNAVAILABLE`）；用例要求原回执墓碑可重放但不得恢复消息。
- GREEN：服务读取 owner/request/target/payload 摘要绑定的原接纳事实；目标仍不可用时，只返回匹配的既有 tombstone，不写入或唤醒。正文或目标不匹配仍拒绝。

## 交付范围

- 新增桌面能力 `action.session.message.send` / `action.session.message.revoke`，发送身份从当前 session context 取得，请求 ID 按 owner session 作用域化；两个能力均为 `act`，复用既有 toolkit 策略入口。
- `createSessionMessageService` 只做 facts 阶段：可见目标校验、持久接纳、请求幂等、失败唤醒保留 receipt、墓碑重放；不产生执行批准。
- SessionStorage 暴露 owner-scoped acceptance read 与 revoke 命令。撤回复用存储 CAS，只有 queued 且无 turn 的输入可以撤回；领取后返回 claimed/settlement。
- 桌面排水入口能在同一持久 FIFO 读取普通 desktop 与可信 agent-session 输入，其他来源不会混入。A02/A04～A07 负责批准、prepare/execute 屏障和实际 agent-session 派发；在这些阶段完成前，agent-session 仍不允许经普通 Outbound 路径启动。
