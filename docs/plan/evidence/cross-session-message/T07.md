# T07 本机整库关闭与回退演练（完成）

## 隔离范围

仅使用 `createTempDatabase()` 创建的临时文件库。演练在迁移前关闭 writer，复制闭库 SQLite 文件作为备份；不访问用户数据目录。

## 过程与结果

1. 建立 v123 旧格式库，写入普通 desktop queued receipt，再把迁移元数据恢复为 v123，并确认 `source_json` 列不存在。
2. 关闭数据库连接，将闭库文件复制为整库备份。
3. 用正式应用 `openDatabase()` 升级生产样本；确认 SQLite `integrity_check=ok`、`foreign_key_check=[]`。
4. 关闭升级库，恢复原备份；用原生 `DatabaseSync` 读取，确认 schema 仍为 v123、原 queued receipt 与 message ID 未变且 FK 完整。
5. 再以应用 `openDatabase()` 打开恢复库，确认重入升级至当前 schema；旧回执仍 queued、`source_json=NULL`，integrity/FK 检查通过。

本演练验证的是同一整库快照回退、旧应用格式可读及升级可重入，不代表已启用生产迁移；备份后写入升级库的更改随整库恢复而丢失，边界符合整库回退语义。

## 验证

`npm exec -- vitest run electron/database/migrations.agentSessionMessage.test.ts`：5 项通过。覆盖文件库 v123→当前 schema、关闭重开、旧回执/FK 对拍、入向外键导致的迁移事务回滚、未来 schema 拒绝，以及本演练。
