# T06 端到端矩阵与 V/AC 追溯（完成）

## 集成证据

本机使用临时 SQLite、替身模型/provider、真实桌面 dispatcher / Hosted handler 与持久 trigger queue，不连接真实 IM 或生产模型账号。

- `claudeStreamHandlers.hostedIntegration.test.ts`：已批准来信由真实临时库 claim；关库重开、恢复原 Turn 后进入 Hosted provider；捕获到 owner/request 来源包装和原正文。source 缺失、消息正文被改写时 provider 调用不增加，原 Turn 按失败路径终结。
- `appIpc.file.test.ts`：真实 app dispatcher 在容量满、final-check 拒绝和直接 IPC 材料损坏时保持零 execute/source/provider 副作用；已有 Turn 的损坏路径会终结原 Turn。
- `triggers/recovery.test.ts`：持久的 Turn terminal / not-executed settlement 经 recovery 关联精确 request，通知使用固定 requestId 落在 owner queue；原 Turn 失败和目标删除（目标删除先于/后于 wait registration）均产生不含消息正文的 owner 通知，重复 scan 复用同一 receipt。
- `triggers/hostService.test.ts`、`authorization.test.ts`、`runtimeMaterials.test.ts`：仅合法 owner / receiver / 来源绑定可登记或接收通知；错误 owner、receiver、payload、policy generation 或 final-check 被拒绝。
- 固定种子状态机、迁移回退、普通 desktop / IM / runtime-trigger 旧入口及共享 admission lane 回归分别见 S01～S08、T01～T05、A01～A09。
