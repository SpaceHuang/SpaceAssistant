# A04 持久接纳核验与 TurnRuntime 守卫

## RED / GREEN

- RED：`npm exec vitest run electron/turnRuntime.test.ts` 新增 `rejects invalid persisted input admission before execute source dispatch` 两个入口用例后失败：`execute` 与 `executeWithSource` 均在 verifier 返回 `source-gap` 后仍解析成功，provider/source 被调用。
- GREEN：两入口在 coordinator/provider/source callback 前调用同一 verifier；invalid/异常/未知 verdict 取消 exact Turn 并抛 `AGENT_INPUT_ADMISSION_INVALID:<caseId>`。普通路径在未装配专用 Runtime 的单元环境保持原时序；SQLite `createSessionTurnRuntime` 自动注入持久 verifier。

## 持久事实核验

`verifyAgentSessionAdmission` 按 session/turn/request/message 精确对齐 Turn、desktop receipt、来源记录、执行批准、目标 generation、已提交 History stream/event 与输入指纹；检查 admission 冻结的 origin/approval/event 摘要。它只核验已批准材料，不运行策略或重算风险。有效 Agent 材料返回 admitted；无来源且历史事件无 Agent 锚点的输入返回 ordinary；缺行、损坏、缺批准、身份/摘要/代次不符返回稳定 case ID。SQLite composition 的 verifier query 缺失时也 fail closed，provider 调用计数为零。普通输入与 runtime-trigger 既有启动 authorizer 保持原流程。

新增不可配置 final-check invariant：`SYS-AGENTINPUT-001`，范围为 `verifyAgentSessionAdmission` 与 `assertPersistedInputAdmission`，失败在任何 source dispatch 前终结 Turn。
