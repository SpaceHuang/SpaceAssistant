# P3-07 拆开首屏辅助请求并复用后台准备

## 已实施

- 首屏 page dispatch 后不再等待 context-summary baseline；压缩 markers 在页面提交后的下一帧再单独排队读取，session 代次不匹配的结果不会更新当前展示。
- 文件数据库的摘要 miss 路径读取 revision 小行后，将只读 SQLite 快照与 thinking／attachments 的轻量列读取放到 worker 线程；计算复用 `projectionForegroundWorkerBudget`。worker 和主进程分别核对 generation／message revision；过期源拒绝，主进程对 source-changed 自动重试一次。
- SessionQueries 为最多 8 个 session、最多 100,000 条摘要项缓存派生结果，并以 generation／message revision 校验命中；超出单项预算的摘要不缓存。`:memory:` 数据库只用于测试，无法由另一个线程共享连接，因此保留测试专用的轻量行读取＋同一 worker 计算路径。
- 同一 session generation 与 message revision 的并发摘要 miss 复用一个 in-flight worker；worker 完成后再变更源会丢弃旧结果并有限重试。
- renderer 侧 live add／thinking 或 attachments patch／remove 更新摘要 override；ChatView 通过 session 过滤的订阅刷新标量。基线未就绪时 usage ring 暂不绘制部分占用，避免把缺失的摘要当 0 后展示错误占用。
- 纯 metadata 解码器移至 `src/shared/sessionMessageMetadataCodec.ts`，供主进程与 SQLite worker 共用，消除 session-storage 模块边界违规。
