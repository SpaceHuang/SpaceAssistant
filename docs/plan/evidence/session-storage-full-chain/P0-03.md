# P0-03 隔离共享规则原型

## 范围与结论

仅使用测试内模型，不接入生产路径。本记录证明AC-13／15所需规则能在隔离原型中表达；不证明协议2生产写入、reviewKey生产事务、receipt读取闭环或P3跨轮缓存已经完成。

## RED / GREEN

- RED：原型首次乱序工具结果用“到达顺序”追加，断言要求按模型调用声明顺序，失败显示B先于A。
- GREEN：原型将工具结果暂存并按调用序释放，后续结果先到不进入工作消息，前序结果到达后按A、B顺序追加。
- GREEN：将隔离原型在同一 park/failure/success 多次压缩输入上与生产 `restoreSessionContext` / `applyContextEvent` / `selectContextCommit` 做逐消息对拍。

## 覆盖

- 成功、普通失败、连续两次压缩后的失败切口及压缩后park保持轮次入口基线；required user缺失时失败选择不可用，但不阻断park或success。
- 工具乱序完成按声明顺序交付；保留图像Canonical载荷、thinking签名和tool thought signature。
- 审批system说明进入工作态，终态持久选择剔除system消息。
- 独立track scope样本互不串入；旧完整seed与旧整数组装结果逐消息相等。
- 复核夹具按 `SHA256(stableEncode(['session-review-v1', sessionId, generation, sourceTurnId, expectedVersion]))` 派生reviewKey，并绑定repair turn、source turn、base/next version。它只用于表达确定身份约束。
- `electron/database/sessionTranscript.test.ts`复用当前已存在receipt事务，覆盖同repair turn同内容重试幂等、同槽异载荷冲突及version绑定；未写协议2新repair stream生产实现。
