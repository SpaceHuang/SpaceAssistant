# P3-03 移除启动普查及全局恢复就绪依赖

## 实现

- main 启动不再调用 History/ledger 全局恢复、turn snapshot/coordinator 恢复、session transcript reconciliation、continuation 全局收敛、streaming 残留全库修复、spill source-truth GC 或孤儿进程全局遍历。
- SessionRecoveryPort 的 SQLite 适配器按目标会话读取本地执行状态；全局历史/ledger 报告不再把其他会话的执行入口一并标成 pending。显式恢复报告中的 execution 级目标失败仍只阻塞对应 session。
- 首次执行目标会话时，在原 session admission 门内先核验活跃 owner；无活跃 owner 才按 session 查询旧 shell 执行身份并调用既有 owner-token 进程验证/清理，再做目标 transcript claim recovery。streaming 无 turn 残留也只在同一目标恢复点按 session 修复。
- 目标孤儿身份 SQL 查询带 session_id；查询只输出 turn/tool identity、PID、进程组和 owner token，不读取消息正文。无法证明进程身份时沿用既有不清理行为。

- 未配置或调用外部大模型；本阶段改动是启动与恢复编排，不依赖模型账号。真实 Electron 重启后残留 shell 进程的 OS 级行为仍由既有 owner-token 子进程验证逻辑负责；本机测试覆盖其目标身份查询与调用路径，不宣称覆盖另一操作系统现场进程行为。
