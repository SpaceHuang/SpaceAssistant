# P3-01 领取前目标恢复（实现验收记录）

## 行为与边界

- 普通 Hosted handoff 在目标 session admission gate 内先检查活跃 owner 并执行 session 限定恢复，再尝试普通 execution claim；同 session 后续 turn 保持 FIFO 排队。
- 目标恢复将既有 stale claim 收敛与 committed transcript reconciliation 限定到单个 `session_id`，不扫描或更改其他 session。未开始的遗留 claim 可按原代次和 owner tuple 释放；已开始但无法证明结果的执行保持 `commit_uncertain`，后续普通 claim 返回 blocked，不重试工具。
- 进程内 owner registry 由 execution claim/release 生命周期维护。真实活跃 owner 存在时不进入数据库恢复，继续沿普通 claim 的 owned/queue 语义等待；不以 owner 字符串或超时推断失效。
- `chat:continue-from-checkpoint` 在来源身份和安全快照核验后、continuation 接纳前经过相同 admission gate 调用目标恢复；active owner / blocked 分别返回稳定拒绝原因，不派发模型或工具。
- SQLite 恢复适配器为执行端提供 `recoverTarget(sessionId)`，原全局 `reconcile()` 仍仅服务尚未由 P3-03 删除的启动编排；目标 handoff 不再调用该全局形态。
- 新测试从无启动恢复状态的 claim 开始，未预清控制行；固定种子 claim/queue/recovery 序列每步核对单活跃 claim 及 claim/queue tuple 一致，并验证 unknown 保持 blocked。

## 审查结论

- 执行恢复资格不依赖普通 claim；恢复 helper 对 stale claim 和 uncertain checkpoint 均按目标 session 查询。
- active owner 不被 recovery 接管；FIFO contender 仍可入队。重启后进程内 registry 为空时，是否允许恢复仍依赖应用已建立原有独占存储隔离，不从 PID/owner 文本猜测。
- 启动全局 `reconcile()` 仍暂留在原启动编排；P3-03 负责删除启动普查与全局就绪依赖。本项所有领取前目标入口均只调用 session 限定恢复。
