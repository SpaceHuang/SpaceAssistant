# P3-05 将状态、预览和列表查询改为必要局部读取

## 已完成实现

- `listSessions` 支持 `workDirProfileId`，与 `user-visible` 条件一起下推 SQL；桌面 `session:list` 不再先加载全部可见 session 再由 JS 按 profile 过滤。
- `session:list` 与 `session:get` 对旧 Plan metadata 只生成返回 DTO，不再通过读 IPC 调用写命令或 `flushSave`。已有全量列表契约保留，没有增加分页。
- turn request 状态仍通过 `turns` 控制行读取；消息 skeleton 与已准备 retry target 只选择 retry 涉及的两条消息。prepared retry reader 在 source identity 变化时拒绝旧投影，worker 的 selected body 结果只覆盖目标 ID。
- 队列重排先比较重排前后的尾消息身份；尾消息未改变时不再读取/重放 History。删除非尾 queued message 时保留已有 session preview，不再读取尾消息正文。尾消息变化且新尾部是 queued row 时，仅从已查询候选 row 计算预览。删除尾 queued message 时，IPC 按 sequence 读取新尾 skeleton，异步准备单条正文；DB 命令用 session generation、message revision、身份字段及 canonical-only 状态在事务内校验后使用预取正文，异步期间任何相关变化均回滚删除与回执变更。
