## 交付行为

- delivery 使用 `runtime-trigger:<triggerId>` 与固定中性 marker；重复调用复用原队列 receipt，缺失/编辑/指纹不符均失败关闭。源正文不进入 marker。
- delivery 先取得宿主批准的 authorization binding 并写回登记；共享 queue source classifier 验证真实登记、requestId、owner/receiver/scope、固定 marker 与 fingerprint；sync trigger 还必须有 `pauseAcceptedBySdk=true`。
- `createRuntimeTriggerStartAuthorizer` 核验准确 receipt/Turn/来源；版本变化时回到宿主 policy reauthorization 并用 CAS 更新绑定，拒绝后取消不可派发输入并记录稳定失败 case。TurnRuntime 对所有 `runtime-trigger:` 请求强制调用宿主 gate；缺失、拒绝或异常都会在 source/provider 前取消。
- `cancelUndispatchedRuntimeInput` 原子删除未领取 marker 并保留 cancelled receipt，或终结 claimed 的 prepared/configuring Turn、更新消息与 receipt，防止重领。
- `SqliteAgentHistory` 接受可信宿主 admission binding；首次 `invocation-context-committed` 在同一 SQLite connection/事务完成批准绑定 final-check、History append 和 `result_json.admission` 写入。上下文与回执任一失败整笔回滚。无 admission 的后续/raw transcript 写入失败；已有 admission 必须和存储 context、request/receiver/turn/invocation/eventId、摘要及授权代次全部一致，已接纳历史不追溯撤权。
- 新增生产 lifecycle assembly，显式使用用户确认的 5000ms/60000ms。
