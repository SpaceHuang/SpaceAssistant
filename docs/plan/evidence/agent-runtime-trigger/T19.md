## 容量与本机时延

测量命令：`npm exec vitest run electron/triggers/capacity.test.ts electron/triggers/recovery.test.ts electron/triggers/migration.test.ts electron/triggers/syncCheckpoint.test.ts`。一次实际样本（Vitest 时间 2026-11-02 02:37:41 +0800；测试输出 wall time 2026-11-01 18:37:41Z；macOS `darwin/arm64`）：

| 量 | 样本结果 | 计时说明 |
|---|---:|---|
| 每 owner 128 次登记 p95 | 0.379 ms/次 | 128 个连续真实 service→SQLite 登记时长排序取 p95 |
| 应用全局 4096 次登记 | 1116.8 ms | 连续 service→内存 SQLite 登记；验证第 4097 条拒绝 |
| 4096 waiting 恢复扫描 | 2.0 ms | 4096 条等待记录真实读出并执行 scan；time 未到期，故不计入恢复成功 |
| 来源事实→队列标记 | 232.877 ms | 一个已到期 time fact 经实际 evaluate/match/recovery/delivery/receipt；队列只含固定中性 marker |
| 5000 项 History 重建 | 3.50 ms | `SettledStepFactsTracker.update` 对 5000 条已持久化形状事件做一次内存重建 |
| 每步单条增量 | 0.540 ms | 同 tracker 对第 5001 条 append 事件做增量更新 |

这组容量 fixture 使用本机内存 SQLite，不含磁盘 fsync、真实 IM/provider 或竞争流量；只有单轮样本，不能解释为生产负载分位数。来源到入队样本低于设计的 2 秒本地目标，但不是多轮 p95/SLO 证明。登记期限、15 分钟/最多 5 次重试、忙碌不耗额度、owner 128/应用 4096 由确定性边界测试核验，未将随机机器耗时作为限额断言。
