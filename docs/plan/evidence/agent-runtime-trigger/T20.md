# T20 关闭与整库回退恢复演练

## 关闭顺序

主进程 `before-quit` 的触发器相关顺序为：

1. 同步设置 `isQuitting`，宿主 trigger service 拒绝新登记（TDD RED 用例先证明缺少闸门时登记会成功；GREEN 后拒绝并返回 `TRIGGER_ADMISSION_CLOSED`）。
2. 停止 recovery interval，并取得正在执行 scan 的 quiescence Promise；新 interval 不再启动，已有异步 source read/delivery 完成后才越过关闭屏障。
3. 取消所有在线 SDK sync waiter，清空 waiter registry；触发器显式 cancel 也能按 triggerId 唤醒对应 waiter。
4. 同步关闭 session event 新生产，启动已有 storage lifecycle stop/quiesce；等待 session projection migration、shutdown cleanup、storage quiescence 与 runtime trigger recovery 全部完成。
5. 仅当 storage 已 quiescent 且未越过 shutdown deadline 时 `flushSave()` 并 `close()` SQLite；否则已有主进程逻辑会跳过数据库关闭，避免带写入关闭。

相关实现：`electron/main.ts`、`electron/triggers/recovery.ts`、`electron/triggers/syncCheckpoint.ts`、`electron/triggers/hostService.ts`。

## 演练夹具

- `recovery.test.ts`：fake timer stop 可重复调用且不会再扫描；另用延迟 source evaluator 证明 stop 的 Promise 在活动 scan settle 前不会完成。
- `syncCheckpoint.test.ts`：shutdown registry cancel 所有已注册 waiter 并清空；二次 cancel 不重复调用。已有测试覆盖显式 cancel 传递至在线 SDK wait、超时及 receiver 终态对账。
- `hostService.test.ts`：关闭 admission 闸门时新 register 被拒绝；RED/GREEN 分别为登记成功和稳定错误。
- `migration.test.ts`：v120 原 schema fixture 升级到当前 schema；注入 schema version 更新失败证明整组 DDL 原子回滚；关闭一致性数据库副本，升级副本后恢复原整库，直接用 SQLite 查询核对恢复版本与旧表结构。升级后创建的 session 在恢复后不存在，证明副本之后的全部数据变化会丢失。
- `electron/database/migrations.automationPreflight.test.ts` 已有高版本库拒绝测试；本轮没有降低版本号、删表或在生产数据库演练回退。
