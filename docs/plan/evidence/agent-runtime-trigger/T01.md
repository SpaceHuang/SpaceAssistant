# T01 实现合同与 fixture 入口（完成）

- 共享 DTO 固定五类 condition、v1 definition、持久态/投影态、五项能力 params、trigger/page/targets/operation returns 与 10 个稳定域错误。服务 owner 只从宿主参数进入，协议 parsers 对未知字段及 Agent 伪造 owner 拒绝。
- SDK lifecycle hook/limits 仍归 `packages/agent-sdk`；显式有限正数是合同，SDK 无生产缺省值且不依赖 shared/electron。T15 实际装配限值由用户确认 `callbackTimeoutMs=5000ms`、`maxPauseMs=60000ms`；协议 fixture 仍使用标注的独立假值。
- `electron/triggers/protocol.ts` 与 `.test.ts` 覆盖 5 类 condition、所有操作输入、输出分页、错误 DTO、callback/pause SDK 失败到 `TRIGGER_HANDLING_FAILED` 稳定 case 的映射及 admission v1 JSON fixture。Admission fixture 的逐字段合同与未接纳失败场景由 T15/T16 真实 History 事务测试承载；不得由本合同测试伪称已验证宿主原子提交。
- Admission v1 字段固定为 `version,triggerId,requestId,receiverSessionId,turnId,invocationId,contextEventId,contextDigest,payloadDigest,authorizationGeneration,policyRevision,acceptedAt`；parser 拒绝额外字段、缺摘要和错误版本。失败 DTO 只携带稳定 code/case 与可选状态/revision，不接受正文/secret 字段。
- 验证：`npm exec vitest run electron/triggers/protocol.test.ts`（后续聚合验证见 T08）；`npm run typecheck:shared`、`npm run typecheck:agent-sdk`、`npm run check:agent-sdk` 通过。
