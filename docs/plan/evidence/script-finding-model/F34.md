## RED / GREEN

- RED：先加入 disposition 与 token contract 测试。初次运行因映射模块不存在、finding 类 token 未产生、路径分类 token 未产生而失败；第一次 token 实现还使 legacy `unmodeled-call` 抢先命中动态执行锁定规则，既有记忆/policy 用例失败。
- GREEN：共享策略域新增 `Record<ScriptFindingClass, ScriptClassDisposition>` 总映射；12 类逐一测试。`native-code-load` deny、`cwd-change` allow、`file-write` 按 pathClass 映射（absolute/dotdot deny、relative allow、unresolved ask），其余类别 ask；运行时未知类别保守 ask。编译期 `Record` 保证新增类别必须补策略映射。
- `signalTokenSet` 对 finding 派生 `script-finding:<class>`、可用时 `script-finding:<class>:<pathClass>`，以及由 disposition 计算的 `script-finding:non-allow`。
- 路径动态类别各自派生 `script-path-extraction:<kind>`。显式非空 dynamicKinds 另派生兼容聚合 `...:dynamic-execution`；当且仅当集合去重后仅有 `unresolved-write-target` 时派生 `...:write-target-only`。未知类别转换为 `path-analysis-unavailable`，不能生成 write token。
- 无 dynamicKinds 的旧形状仍按已有 `dynamicAccess` / `unknownReason` token 决策，同时增加 `path-analysis-unavailable` 类别 token；不人为添加聚合锁定 token，避免改变原有 `unmodeled-call` 规则次序与记忆边界。
