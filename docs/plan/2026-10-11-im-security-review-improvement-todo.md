## 执行约定

- 状态只使用 `- [ ]`（未开始）、`- [~]`（执行中）、`- [x]`（已完成）。
- 严格按编号顺序执行；先决任务未完成，不开始后续任务。任何时刻最多一项为 `- [~]`。
- 开始任务前先将该项标记为 `- [~]` 并保存；达到该项验收条件后，将其标记为 `- [x]`，在其下记录命令、结果和文件/审计证据，再开始下一项。
- RED 任务的完成标准是：在指定测试文件/用例中记录因目标行为缺失产生的预期失败；该预期失败允许进入对应 GREEN。语法、导入、夹具、环境错误或无关基线失败不是有效 RED，须先修复或登记。
- GREEN 任务的完成标准是：对应 RED 用例通过，并通过追踪表列明的必要聚焦回归；只有 GREEN/验收失败才阻止进入后续依赖任务。
- 每项任务开始前，先在任务描述或追踪表补齐目标模块/文件、测试文件/用例名、最低验证命令和通过标准；允许先修订本计划，再改代码。
- 若任务无法完成，保留 `- [~]` 并记录首个错误、相关调用栈、预期/实际结果和下一步；不得绕过失败进入后续依赖任务。
- 发现任务仍包含多个无法独立验收的行为时，先修改本计划拆分并校正编号，再开展该任务。
- 先记录 `git status --short`。只修改正在执行任务列明的目标文件，不覆盖既有工作区改动。
- 本地测试使用仓库测试框架、临时数据库/文件及 fake adapter/provider；不得用真实用户数据或生产 IM 账号。现有门禁未通过前，不启用自动审核或普通回复例外。
- 每个行为变化先补相应测试，再实现；完成对应阶段时运行本计划列明的聚焦验证。全量测试、构建和启用验证只在明确列出的门禁任务中执行。
