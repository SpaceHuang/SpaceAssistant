## B01 [P1] 目录校验完成判据未覆盖每个工具的最终派发边界

位置：任务 5.1（第 173–175 行）、5.3、5.5。

需求 FR-04 明确要求“响应返回后、任何工具派发前”再次核对绑定。计划 5.1 的完成判据只指定 provider response 到达时比较 binding，5.3 另行覆盖审批恢复，仍没有明确普通工具在调度排队、资源锁等待后真正进入 executor 前的来源绑定校验。

触发场景：A 的请求返回一批普通工具，响应检查通过；其中一个工具等待资源锁或前一工具完成，期间外部把会话绑定切到 B；后续工具才创建或刷新执行上下文。`electron/runtime/invocationAssembler.ts:842` 按动态 `resolveWorkDir` 创建上下文，因此可能以 B 的有效上下文执行 A 请求产生的操作。即使现有安全机制重新审批并允许 B，也不能代替“操作必须仍属于来源请求绑定”的校验。

代码依据：`packages/agent-sdk/src/turn.ts` 的工具流程在资源锁获取后才进行 `prepareTool(..., { kind: 'recheck' })`，随后授权并执行；这些异步等待说明响应检查与实际派发不是同一边界。现有 initial/recheck 比较可用于拒绝准备后变化，但不能单凭它证明工具首次准备前已变化时会与来源模型请求比较。

修订要求：5.1 明确每个工具都携带来源逻辑请求的目录/绑定身份，并在最终派发或既有 claim/recheck 边界比较；覆盖普通工具、只读工具、队列和资源锁等待，不能仅比较工具自己 initial 与 recheck 的身份。阶段 0 核实已有机制是否足够，足够则记录代码与回归证据，不另造调度器。校验与 executor 使用的目录必须保持一致，不能校验 A 后再动态解析 B。

补充测试：响应检查通过后暂停工具调度或锁获取，外部切换 A→B，再恢复。断言尚未派发的工具 executor 未进入，返回未执行结果；已执行工具不重放；下一模型请求加载 B 指令。另覆盖同批前一普通工具执行期间切换、无审批的只读工具。

## B02 已撤销阻断：正常并发写入与可选加固的边界

位置：任务 2.2–2.3、2.6。

其他进程写入、编辑器原子保存、文件修改与删除都是正常使用场景，应兼容，不视为攻击。本期读取器的验收边界为：

- 兼容正常修改与原子替换；读取完整版本，发现不稳定时有界重试，仍失败则明确降级，不复用旧正文。
- 保留既定字节/token 上限、普通文件检查、路径边界检查；明确的越界符号链接或非普通文件拒绝加载。
- 不要求为了刻意卡在检查与打开之间的恶意替换，新增跨平台父目录防替换、复杂句柄身份验证或 FIFO 替换对抗机制及测试。这些仅属可选加固，不是本期实施、提交或验收的前置条件。

撤销原因：此前未提供足以支持该威胁模型的产品场景或风险证据。拥有同等本地权限的恶意程序不应成为本功能不断扩张防护范围的理由；正常并发写入也不能被用来推导强对抗要求。

需求 FR-05/A16 中的读取竞态要求按上述正常并发兼容性和基础路径检查范围理解，不再据此要求强对抗防护。建议后续同步收窄需求措辞，以免执行者重新扩大范围；本次仅更新评审意见，不修改需求或开发计划。
