# 工作目录 AGENTS.md 指令支持需求评审

日期：2026-10-14  
对象：`docs/requirement/agents-md-workdir-instructions-requirement.md`  
结论：存在 2 项阻断，需要先统一调用边界与验收契约，再进入实施。仅评审根文件能力，不要求增加子目录支持。

## B01 [P1] 同调用工作目录冻结与既有主动切换能力缺少兼容决策

需求位置：FR-04 第 92–94 行；第 5 节。第 93 行要求“已运行调用仍绑定原目录和原快照”，但未定义当前 Agent 主动调用 `switch_work_dir` 后的行为；第 5 节只说明 shell `cd` 和子目录工具访问，不覆盖会话工作目录切换工具。

代码依据：

- `electron/tools/workDirExecutors.ts:57`：远程 `switch_work_dir` 会立即更新会话绑定，切换后撤销旧目录写授权。
- `electron/tools/workDirExecutors.test.ts:363`：明确验证持有当前请求租约的 Agent 可以主动切换目录。
- `electron/runtime/invocationAssembler.ts:727` 等工具执行路径通过 `materials.resolveWorkDir?.()` 获取目录；`electron/workDirSnapshot.ts` 也提供绑定变化后的刷新能力。现有契约并非所有工具始终固定初始目录。

触发场景：调用从 A 开始并加载 A/AGENTS.md，随后通过 `switch_work_dir` 切到 B，再继续调用文件或 shell 工具。只冻结提示材料会出现 A 的约定用于 B 的操作；若为满足需求同时冻结全部工具目录，则切换返回成功却继续操作 A，改变既有功能语义。两种行为不能由接入点各自决定。

修订要求：明确区分外部修改绑定与当前 Agent 主动切换，并选定切换成功后的调用边界策略。若坚持同调用目录与指令都冻结，需明确切换仅对下一调用生效的产品行为，或切换后结束当前调用、经新调用加载 B 的指令后再继续；同时交代后续工具、审批和旧授权的处理。无需在需求中规定实现签名，但必须给出唯一可验收行为。

补充验收：A、B 各含不同指令；同轮主动切换后继续读写；切换与其他工具位于同一批次；审批等待期间外部切换。断言实际工具目录、实际 provider 指令与授权边界一致，并断言没有重新执行已产生副作用的工具。

## B02 [P1] 重启恢复的验收没有区分历史还原与可执行恢复

需求位置：FR-04 第 94、96 行，A08–A09 第 164–165 行。FR-04 允许原快照不可恢复时显式中止或开启新调用；A09 却统一要求“原调用可还原原快照”，没有说明这是只读历史展示，还是重启后继续执行原调用，也没有覆盖正文缺失的允许分支。

代码依据：`packages/agent-sdk/src/history.ts:339` 明确约定进程重启后不把 parked / in-flight 工作恢复成可执行状态，`rebuildInvocationStates` 将未完成模型请求、待审批和未确定工具派发还原为 `interrupted`。因此保存并展示旧指令快照与继续执行旧 invocation 是两项不同能力。

影响：实施者可能为了通过“重启后恢复”验收扩展 SDK 可执行恢复，超出项目指令能力范围；另一实现选择按现有契约中断并新建调用，虽符合 FR-04，却无法确定是否满足 A09。仅声明保持 SDK 架构不能消除这项验收歧义。

修订要求：明确本期不因项目指令引入进程重启后的可执行恢复；将 A09 拆成旧调用历史/快照只读还原、重启后新调用加载当前版本、历史材料缺失时显式不可还原三类。A08 单独限定进程内确实保留同一 invocation 的重试或等待恢复。若确实需要跨重启执行原调用，应另行评审恢复与副作用一致性契约，不能隐含在本需求中。

补充验收：持久化旧快照后修改或删除磁盘文件并重启，旧调用查看仍显示旧版本，新调用使用新版本；缺失旧正文时明确不可还原，不以当前文件冒充；未完成调用仍遵循现有 interrupted 语义，不自动重放工具。
