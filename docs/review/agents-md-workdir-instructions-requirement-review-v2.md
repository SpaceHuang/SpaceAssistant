## B03 [P2] 文件刷新改为请求边界后，恢复、验收与状态仍沿用调用边界

需求位置：FR-04 第 97–98 行、FR-06 第 123–125 行、A07–A08 第 169–170 行、决策汇总第 213 行。

FR-04 第 97 行明确“文件内容变化本身从下一 provider 请求边界生效”；第 98 行却要求同一 invocation 等待恢复沿用当时快照，“不能静默换用磁盘新内容”。A07 仍以“下一新调用”描述刷新，A08 与决策汇总仍以同 invocation 复用快照描述恢复。文档已区分 invocation 与 provider 请求，因此不能将这些表述当作同义词。

触发场景：同一 invocation 在目录 A 发出请求 R1，工具进入审批等待；等待期间仅修改 A/AGENTS.md，目录及绑定版本均不变。审批完成并取得工具结果后发出后续请求 R2。按第 97 行 R2 必须采用新正文；按第 98 行和 A08，等待恢复须复用旧正文。当前文档没有说明“恢复”只保护待派发工具与原请求重试，还是也覆盖恢复后的后续模型请求，无法写出唯一测试断言。

另外，FR-06 的“下一调用生效”和“当前调用实际采用的快照”仍假设一次调用只有一份有效快照，而新规则允许一次 invocation 因文件修改或目录切换采用多份。状态面板如仅提供调用级单份快照，会无法准确解释某个请求或工具当时依据的规则。

修订要求：

1. 明确一次逻辑 provider 请求及其重试复用旧快照；旧请求产生的待审批工具是否继续依据该快照也需明确。将“恢复不换正文”限定到这些已有操作，或改回同目录 invocation 内冻结策略，二者选择其一。
2. 若保留请求边界刷新，明确审批完成后的后续逻辑请求 R2 重新读取当前正文；同步修改 A07、A08 和决策汇总，避免 invocation 级复用覆盖请求级刷新。
3. 区分开关变更的 invocation 边界与文件内容变更的请求边界；状态提示分别表达实际生效时点。只读查看需能够关联到具体请求/快照版本，保留旧请求依据，不以新快照覆盖其展示。

补充验收：目录与绑定不变时，在普通工具执行期间、provider 重试期间和审批等待期间修改同一文件，分别断言原请求/重试、待派发工具及下一逻辑请求采用的版本；同时校验状态展示与实际 provider 请求一致。该测试不需要真实模型或 IM。
