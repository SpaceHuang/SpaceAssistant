## 0. 需要决定什么【人必读】

**一句话**：把"会话记录文件与数据库必须互相证明一致、证明不了就不让用户发消息"这套校验拆掉，改成"不一致就以数据库事实为准继续跑，文件慢慢补"。目标不是少报错，是这类错误**不再能中断对话**。

**只有 3 分钟**：只读 D-1（要不要继续拒绝用户）、D-2（能不能删那些校验字段）、D-3b（压缩记录丢了的老会话怎么处理）。

### D-1｜会话记录文件出问题时，是让用户继续说话，还是继续拒绝？

**背景**：现在每次发消息前，程序要先证明"这次会话的事件记录文件"和"数据库里的历史"逐字节一致。证明不了就报错，这一轮对话直接失败，用户只能反复点"继续"碰运气。最近 7 天的运行记录里，这项检查被调用 162 次，其中 33 次判定不通过；有 6 次直接把整轮对话打死，集中在两个会话上，其中一个连续失败 4 次、隔了一天才偶然恢复。

**要决定什么**：
- A：保持现状——证明不了就拒绝，用户自己重试或重启。
- B：改为继续对话，以数据库事实为准；文件能写就顺手补，写不进去也不挡这一轮。

**选 A 的后果**：用户随时可能被一个他看不见、也无法自行修复的检查挡住；数据最保险，绝不使用可能不一致的记录。
**选 B 的后果**：对话不再被挡。数据库健康时，即使文件长期写不进去（目录只读、磁盘满），这一轮照样能发出、能提交；代价是那段时间没有可回放的日志明细，排障信息变少。历史不会被改错：写入的权威在数据库。

**评审后修订（2026-10-22，已确认）**：上一版写的"损失只有重建那几秒"只在**文件还能写**时成立；持续不可写时不存在"几秒后恢复"。因此 B 的后果改为：**对话与提交不依赖文件能否写入**，文件只承担可回放的明细日志。

**可逆性**：B 保留一条立即退回 A 的路径，可随时反转。
**依据强度**：33 次拦截 / 6 次中断来自生产运行记录（**历史日志口径；2026-10-28 代码核对未重复认证这些数字**）；"文件不可写时仍能完成回合"需在 P3 验收（AC-S6），不是本决策的既有事实。
**推荐**：B。
**你不决定时默认怎么走**：维持 A，本计划无法开工。
**状态**：**已批准 B**（2026-10-22）；**后果修订已确认**（2026-10-22）。

### D-2｜允许把台账的"校验字段"和"待办明细副本"缩小、最终删除吗？

**背景**：为了做上面那套证明，数据库里额外存了 **7 个**"文件指纹"字段（文件身份、字节数、尾部帧、索引序号/条数/字节，以及仍在写入的**索引最后写入时间 `proof_index_last_at`**），以及一份"每条待办应当写成什么内容"的完整副本。它们只服务于这套证明。D-1 选 B 之后，这些字段不再承担判断作用——但**逐列处置必须先冻结**（见 §4.3"证明字段清单"），尤其 `proof_index_last_at` 仍被 readiness 的四处 UPDATE 写入，不能按旧的"六列"口径直接删。

**要决定什么**：
- A：全部保留，只在代码里停用。
- B：先停用、演练两段回退矩阵，再物理删除。

**选 A 的后果**：数据库体积和写入量继续背着；两套语义长期并存，后续改动很容易再长回来。
**选 B 的后果**：结构变小、写入变少；代价是升级后的库不能被旧版本直接打开，必须先发布兼容回退包（重构方案 §7.2.1 的 R），且删除不可逆。

**可逆性**：B 的第一段（停用但保留列）可逆；物理删除不可逆。
**依据强度**：字段清单已核对；回退包尚未就位（未验证前提）；**本机候选包只够隔离演练，正式库删除另需该平台 R 发布（AC-S10）**；删列后格式的回退证据由 `P5-T2b`（路径 B）/ `P5-T2c`（路径 A）的第二段按所选路径分别提供。
**推荐**：B（先停用 → 两段演练 → 再删）。

### D-3b｜压缩记录丢了的老会话，模型该看到什么？

**背景**：先澄清一点——**没有专门删压缩记录的机制**。清理任务只删整个会话目录，且"会话还在列表里""数据库有压缩事件""文件里有压缩记录"三者命中其一就保留。所以这个场景只有一个成因：**整个台账文件丢了或坏了**（手动删、同步工具、磁盘异常），而消息本身还在数据库里；上一轮生产数据里发生过一次。升级后压缩事实会入库（P2-T2），这类"记录只存在文件里"的情况会逐步收敛到 0。**本决策只针对升级前形成、文件已丢失的会话。**

**要决定什么**：记录补不回来，处理一定是有损的，问题是选哪种损失：
- A：**按原压缩轮次重放**——把当时的原始消息按原来的窗口边界重新压几轮，生成新摘要。上下文量级接近原来，能继续跑；代价是新摘要与原版不同（模型可能"忘"细节），因此必须在界面明确提示"本会话的早期摘要已重新生成"。
- B：**全量展开**——把原始消息全塞回去，不重写摘要；长会话大概率超模型窗口，只能给"请手动压缩"的提示。
- C：拒绝这类会话继续对话。

**选 A 的后果**：能继续跑、上下文接近原样；有损且会告知；会写入新的压缩事实。**选 B 的后果**：不写任何东西，但长会话多半跑不起来。**选 C 的后果**：等于回到拒绝。

**可逆性**：A 写入新摘要，重放一次后固化（可清理）；B/C 不写。
**依据强度**：成因与影响面来自生产数据（文件丢失 1 例）；重放能否复现原量级需用例验证（AC-S5b）。

**分档规则（三档，避免凭空造压缩、也避免伪造原边界）**：
1. **无法确认是否压过**（`compaction-unknown`）→ 不重放，全量展开（可能本来就没压过，重放等于凭空造事实）。
2. **确认压过且轮次/边界可核验**（`window-lost/replayable`）→ 按原轮次、原窗口边界重放（AC-S5b）。
3. **确认压过但轮次/边界不可核验**（`window-lost/unreplayable`）→ **新切分重压**：按当前历史与预算重新规划窗口，明确标记为"新切分"而非原轮次复现（AC-S5c）——不猜原边界、不伪造轮次，量级可能不同但能继续跑。

**重放所需最小事实**（缺任一项即降为第 3 档）：轮次、每轮输入范围（被压消息集合与顺序）、先后关系、来源可核验。这些元数据可能随台账与检查点一起丢失，因此"能确认压过"不等于"能按原轮次重放"。

**推荐**：A（可用性优先，有损但可见）。
**状态**：**已确认方向（2026-10-22）：允许有损重放，取消三选一，按 A 执行**；重放轮次上限与提示文案在实现阶段给出。

**边界**：第 3 档的新切分也失败（模型不可用或仍超预算）时，退回全量展开+提示，不阻塞对话。

## 1. 目标、前提与不做什么【人机共读】

### 1.1 目标（可观测，按阶段分层）

本计划关闭时，同时成立：

1. 人为破坏会话记录文件（删除 / 截断 / 索引不符 / 目录只读 / 磁盘持续满）后，用户**仍能继续发消息并拿到回复**；回合不依赖文件能否读或写。
2. 已压缩且**事实可恢复**的会话：文件不可用时仍使用同一有效窗口。
3. 已压缩但**事实缺失/无法确认**的会话：按 D-3b 裁决执行；未获批时只登记、不切换，并明确不计入"已完成"。

5. 发消息前的这项检查**不再读文件内容**（AC-S7a 结构性断言），单次耗时 p95 不高于 10ms（AC-S7b 本机串行口径）。

### 1.6 状态与持久表示（SYS-1｜P4 开工前必须二选一）

**问题**：计划把七态降为 `absent/usable/stale`，但**物理列** `session_ledger_projection_state.state` 的 CHECK 只允许旧七态（`schema.ts:2007`，v101），旧 outbox 入队/ack 仍写 `dirty`/`unknown`；同时 P4-T2 的"`expected_*` 保持空"与三列 **NOT NULL 且无默认值**冲突（`schema.ts:2045–2047`，v102）。隔离 SQLite 探针已确认：三态 UPDATE 会被 CHECK 拒绝。**未定表示之前不得执行 P4-T1。**

| 决策点 | 现状（2026-10-28 代码） | 必须固定的契约 | 落点 |
|---|---|---|---|
| 逻辑状态 vs 物理状态 | CHECK 仅 `uninitialized/initializing/unknown/checking/ready/dirty/blocked`（`schema.ts:2007`） | **已选映射式**：三态只读映射，不迁移 CHECK、不改物理 writer；缺失记录→`absent`，`ready`→`usable`，其余六态→`stale`。原因：不改变已有持久状态语义，后续仍可单独调整读取判定。**只改 TypeScript 联合类型不算完成契约** | P4-T0 → P4-T1 |
| 旧状态残留 | outbox 入队/ack 仍置 `dirty`/`unknown` | 物理七态全部保留，当前无状态退休：`uninitialized` / `initializing` / `unknown` / `checking` / `dirty` / `blocked` 都映射为 `stale`；`ready` 映射为 `usable`。`blocked` 的具体失败原因仍由 `failure_class` / `retry_scope` 表达，不因逻辑映射丢弃。代码与隔离 SQLite 测试已验证七态可写、三态仍被 CHECK 拒绝 | P4-T0/P4-T1 |
| 无载荷 target 编码 | `expected_events_json`、`expected_event_ids_json`、`payload_sha256` 均 **NOT NULL、无默认值**（`schema.ts:2045–2047`） | **已选版本标记**：两个 JSON 列均写唯一对象 `{"encoding":"canonical-v1"}`；reader 仅在两列都恰为该单字段对象时识别为按 canonical 身份生成，单边标记、额外字段或未知版本均报错。`payload_sha256` 保持现有算法 `SHA-256(stableJson(canonical 派生 expectedEvents) + NUL + stableJson(canonical 派生 expectedEventIds))`，不对哨兵文本求摘要；canonical 重建后比较该摘要。旧数组行继续解析，并按旧算法校验摘要。新格式与三列 NOT NULL 兼容；生产者停写正文归 P4-T2，实际 canonical 重建 / 混合队列消费归 P4-T3 | P4-T0（表示 / 解码）→ P4-T2/P4-T3 |
| 混合队列 | drain 直接 `JSON.parse(row.expected_events_json)`（`sessionLedgerOutbox.ts:380–381`） | 兼容 reader 必须能同时处理旧载荷行与无载荷行；**旧格式夹具先于首次生产停写**，不能留到 P5 删列 | P4-T2 |
| 回退 | 两段回退矩阵（§5.3） | 映射式天然可退；替换式需 CHECK 回滚脚本 + 旧 reader。回退证据与删列矩阵同批 | P5-T2 |

**判据（见 §1.3；本任务只关闭"表示/解码层"）**：**按所选分支**验收——**映射式**：物理旧七态仍合法、逻辑三态映射完整、**物理新三态仍被 CHECK 拒绝**（负例）；**替换式**：新 CHECK 接受三态、存量逐态迁移、writer 全部切换。两种分支都必须有无载荷编码 + 识别规则 + digest 来源，且旧格式行仍可解析（AC-S12）。**混合入队 / drain / ack / reopen 属 P4-T3（AC-S12b）**，不在本任务关闭；生产停写属 P4-T2。

### 3.3 顺序理由（十一条，不可调换）

1. **P1 只断准入，不承诺对话成功**：回合内读写尚未迁移（R2-1）。桌面回合已在 `6554a671` 提前降级（`ledgerReady=false` 时跳过台账读写），故 P1 的剩余改造集中在 IM / butler / 恢复宿主 / `readContextMeterEvents` 4 处。
2. **P2 全部事实准备必须早于 P3 消费者切换**：否则"读数据库"读到空事实。
3. **持续写入契约（P2-T2）不可省**：一次回填不保障以后新压的窗口。
4. **幂等重建（P3-T2）必须先于"恢复后自动收敛"的验收（P3-T3）**：重建实现若留在 P5，P3 的收敛判据就依赖后继任务（R3-2）。收敛验收含 **AC-S6b**：耗尽后唤醒、无新消息收敛、固定种子并发不变量（T-3）。同时 **P3-T1 只按 AC-S5a 验收**（消费端降级），全矩阵归 P3-T3（R4-1）——否则先行任务又提前要求后继能力。
5. **P3-T1 的缺失/未知分支受 D-3b 门禁**：未批不得接通，AC-S4 不通过。
6. **P4-T3 先清账、再按类型迁移与停写**：先用现有实现 drain 旧 pending（不可达项显式登记），再改执行材料；停写**只作用于已迁移类型**，未覆盖类型保留载荷（R6-1、R7-1）。**证据同样按此拆开**：P4-T3 只凭 AC-S9a-1 关闭（消费者迁移），停写证据 AC-S9a-2 与联合 AC-S9a 由 P4-T2 关闭——不得要求后继任务的反向证据（T-1）。
7. **"按类型停写"与"全表删列"是两个门槛**：P4-T2 只停写已迁移类型；**路径 A（完整删列）**要求全部生产类型 + **全部存量义务**处置完毕（AC-S9b），**路径 B（保守）**只删 proof、保留 outbox 载荷（AC-S9c）。两条路径各自闭合，不互相挡（R7-1、R8-1、R8-2）；依赖表已拆为 `P5-T2a/b/c`，**A 未通过不得阻断 B**（R10-1）。
8. **P5-T0 先产出两个脚本变体，再在隔离库分别演练**：变体①（完整删列）对应 `P5-T2c`，变体②（仅删 proof）对应 `P5-T2b`；**脚本的 DROP 列范围逐列取自 P4-T2 已冻结的七列处置清单**（保留列不得因命名被删）；脚本不得在正式库执行；`P6-T1a` 只把已演练的变体应用到隔离库，`P6-T1b` 才允许动正式库（R7-2、R8-2、AC-S10、MR-1）。
9. **P5-T1 只做启动维护接线，不得再隐含实现重建**：同一能力不得在两个阶段各隐含一次。
10. **P5 的回退矩阵必须早于 P6 的删除，且"隔离演练"与"正式删"分开**：隔离库演练（P6-T1a）需 D-2、**本机 R 包工件**、该路径 AC-S8、AC-S9b/S9c；**正式库删除（P6-T1b）另需该目标平台的 AC-S10**（R 已发布且可下载、hash 可核验、已签收、先 R 后迁移版本）——本机候选包**不能**替代平台发布门禁（TA-5）。其余外部项（真实渠道、7 天窗口）不在门槛内。
11. **P4-T0 必须先于 P4-T1（SYS-1）**：三态与无载荷 target 都不是纯类型问题——物理 `state` CHECK 只允许旧七态、outbox 三列 NOT NULL 且无默认值。先定表示并完成迁移/兼容 reader，再上判定；否则 P4-T1 首次写入即被 CHECK 拒绝、P4-T2 首次生产入队即失败。

**注入口径（决定"本机可验证"的边界，T-3/T-4）**：

- **ENOSPC 只限定台账**：注入到台账目录/文件接口（spy 或可注入的 writer），**不得填满承载 SQLite 的同一卷**；AC-S6 要求"台账失败而数据库健康"，卷级填满会同时破坏数据库，使该判据无法成立。
- **只读注入必须证明生效**：`chmod` 成功不等于写失败；用例须断言目标写操作确实返回 EACCES/EROFS，否则按"注入无效"判不通过。
- **模型请求用确定性替身**：本机自动验收用替身完成"请求发出 + 回合提交"；真实模型服务另列集成证据，不把账号/网络当本机前置。
- **崩溃证据分层**：子进程 kill/reopen 的故障注入在本机做；真实掉电与 Electron 完整进程强杀仍另列外部验收。
- **调度类必须固定种子**：AC-S6b 的并发交错用固定种子随机操作序列 + 状态不变量断言，单次连跑两次不作为证据。
- **负例必须保留**：越界写被拒、canonical 源损坏**不得**被伪装成"台账降级"、伪造 bootstrap provenance 被拒——降低可用性门禁不等于放宽写边界（SYS-2）。

### 5.3 两段回退矩阵与按路径关闭规则（P5-T2a/b/c 的放行条件）

**第一段：删列前（旧列俱在、代码已停写）——属于 P5-T2a，两条路径共用**

1. 回退包能读能写新库。
2. 新写入若干会话 → 回退包读取，不发生内容错乱。
3. 回退后二次升级 → 新代码读取，不重复投影、不丢回合。

**第二段：删列后（隔离库，执行与所选路径相同的迁移）——按路径分别执行**

- **路径 B（默认）→ P5-T2b**：用仅删 proof 的迁移；载荷列保留。
- **路径 A → P5-T2c**：用完整删列的迁移（含 proof 与 outbox 载荷）。

> 下面 4–7 步**只在隔离库执行**，全程不触碰正式库；正式库删除另见本节末「正式库删除」与 AC-S10。

4. 隔离库执行**该路径**的删列迁移 → 新代码正常新写。
5. 指定 R 包读取、写入、reopen 删列后的库。
6. 再由 R 升回新版本 → 新代码读取，数据与失效协议一致。
7. 记录**本机可产出**的产物 manifest 与 hash；任一步失败：**停止该路径的隔离演练**，不得转而在正式库删除；另一条路径不受影响，可单独关闭。

**按路径关闭规则（R10-1 解除要求，唯一判定口径）**

| 路径 | 关闭条件 | 未通过时 |
|---|---|---|
| B（默认，仅删 proof） | `P5-T2a` 第一段 1–3 全过 + `P5-T2b`（AC-S9c + 该路径 AC-S8 + 载荷保留 + 旧 pending drain/ack）全过 | 停在 B，不得在正式库删 proof |
| A（完整删列） | `P5-T2a` 第一段 1–3 全过 + `P5-T2c`（AC-S9b 含存量处置 + 该路径 AC-S8）全过 | 只登记原因（如 `source-missing` 旧载荷不可等价重建），**不阻断 B**，也不改变 B 的关闭结论 |

- `P5-T3` / `P6-T1a` 的前置是 **`P5-T2a` + 所选路径子项**：选 B 时不得要求 `P5-T2c`，选 A 时不得要求 `P5-T2b`。

**正式库删除（P6-T1b）与 AC-S10——本节唯一的"动正式库"出口**

- 上面两段矩阵、1–7 步与按路径关闭规则**只产出隔离库证据**，**不授权**任何人对正式库执行删列。
- 正式库删除**按目标平台逐平台判定**：该平台 R **已发布且可下载**、hash 可核验、已签收；发布顺序为**先发布 R、再发布迁移版本**；退休字段前已复验"退休后的升级副本"（AC-S10，重构方案 §7.2.1）。
- **macOS 本机候选包只能支撑隔离演练与源码验收**，不能替代其他目标平台的发布门禁（TA-5 反例：本机全绿而 Windows 无可取得的 R 时，不得删正式库）。
- 某平台缺任一证据 → 该平台保持"**未应用到正式库**"；不影响其他平台，也不影响源码验收与计划按源码关闭。
