### D-1：是否允许增加可重建的分页正文存储

背景：现在读一页可能需要扫描整个会话；把工作放到后台线程只能减少直接阻塞，仍要等数据处理完。要稳定降低大会话切换耗时，需要能够直接定位少量消息正文。

- **A（已批准）：** 增加可重建的分页正文缓存与定位记录。用户界面和对话内容保持现有语义，读取只处理所需页；代价是新增内部存储格式、升级兼容与恢复测试。
- **B：** 只优化现有格式、调度和重复校验。改动小，但首次打开和整份缓存扫描的耗时仍可能随历史增长，不能承诺大会话首屏稳定。
- 可逆性：A 的数据只作派生缓存，回退可忽略并删除新缓存，保留原始对话记录；旧缓存不能在新读取验收前清理。
- 依据强度：整份缓存扫描与同步准备已由源码确认；真实库的收益幅度未测。
- 当前执行方向：按 A 推进；保留 §5 的 P2 详细设计与定位可行性门禁。对应 §3–§5 与 AC-3/4/6。

### D-2：是否改变失败原因与消息的显示顺序

背景：目前页面拿到消息后，还要等失败原因查询完成才显示。将这两步分开可以更快显示正文，但失败气泡可能短暂使用现有通用提示，再补上具体原因。

- **A（已批准）：** 正文先显示，具体失败原因随后补齐。代价是原因存在短暂补齐过程；仍须阻止旧会话结果影响当前会话。
- **B：** 保持当前顺序。显示行为不变，失败原因查询继续计入首屏等待。
- 可逆性：可独立回退到原顺序，无数据迁移。
- 依据强度：串行等待已由源码确认；其真实耗时占比未测。
- 当前执行方向：按 A 推进，纳入 §5 的 P1-R 独立渲染层阶段；不增加新入口、提示或开关。

#### D-2 界面归属卡（记录本次批准范围）

1. **入口：** 现有聊天区历史失败消息气泡，具体原因原本就在此显示，无需新增入口。
2. **形态：** 正文页先提交显示，原因未就绪时沿用现有通用失败提示，查询成功后原位补齐；查询失败保留通用提示，不阻塞正文。
3. **样式来源：** 沿用既有气泡、失败提示组件及主题 token；不新增组件样式、加载提示或文案。
4. **改造范围：** 仅调整既有消息与失败原因的显示时序；无新面板、按钮或设置项。
5. **成本：** 用户无需新增操作；开发需维护原因晚到、查询失败、重复请求及快速切换的状态隔离测试。此卡具体化用户已批准的 A，不扩大交付范围。

失败原因结果只能更新同会话、同显示请求代次且仍存在的目标消息；A→B→A 时，首次 A 的旧结果也不能覆盖后来 A 的新状态。实现前按交互指南完成方案期审查，实现后完成对应界面回归。

**不需要你决定：** 计时点、脱敏方式、性能夹具、SQL 查询计划检查、竞态测试、内部代码拆分由开发负责。本方案不新增设置开关，不修改现有 IPC 入参/返回值，不允许以显示旧数据换速度。

### 是否接受旧会话首次建立快速定位记录时的等待

目前的历史记录没有“消息 ID 到正文来源事件”的完整地图。源码探针已复现：后续压缩事件会改写早先消息 ID 的正文，按当前轮次查找会漏掉新正文。对从未建立过地图的旧会话，要准确知道一条消息的最新正文来源，必须先读完整历史；不能只凭最后一段记录安全推断。

- **A：建立可恢复的持久定位记录。** 新写入在原有保存事务中同步更新消息到来源事件的地图；已有会话由后台工作线程分段补建。尚未补建完成的大型旧会话，第一次打开仍可能等完整历史扫描结束才显示消息，但扫描期间界面不冻结、设置等界面仍应响应；补建后同一会话的后续切换按页读取。需要新增内部数据库格式、升级、回填、事务与恢复测试。
- **B：不新增持久定位记录。** 保持现有历史读取方式；不增加数据库格式和迁移，但大型会话每次冷读仍可能重复付出全历史成本，界面卡顿风险也继续存在，无法保证切换优化目标。
- **可逆性：** A 的定位记录可从原始 History 重建；回退只停用并删除派生记录，原始对话不受影响。回填前后均保留现有读取入口。
- **依据强度：** 完整 reducer、后续 compaction 覆盖旧 ID 的反例、正文块按页原型已在本机复现；尚未在安装包/真实库测量回填时间或首次旧会话体验。
- **推荐：A。** 它消除后续重复扫描，并把首次旧会话的成本移到可恢复的后台工作；首次打开旧大对话仍可能较慢。未获批准前，不实施新的数据库字段/表。

选择 A 也意味着调整 INV-3、AC-4 与 AC-7 的适用范围：完整索引后的页读取必须满足固定成本；旧会话尚未完成首次回填时，完整扫描作为独立的一次性冷启动成本报告，不计作满足“冷首屏不等全会话工作”的 INV-3、冷读 AC-4 或普通冷首屏 AC-7 阈值。若要求未索引的旧会话也必须跳过全历史扫描并立即返回正确页面，当前历史格式没有足够的来源映射，D-3=A 不能满足该要求。

下钻：D-3、§4.2–§4.3、D-1=A；P2-02 原型证据 `docs/plan/evidence/session-switch-performance/p2-02-prototype.md`。

1. 先建立端到端归因与规模基线，区分排队、数据库、Worker、缓存扫描、IPC 和渲染。

## 2. 测量规格【机｜人工可跳过】

每次切换建立关联 trace（开发诊断，不写消息内容）。分别记录：点击/选择、发起分页、准备等待、身份检查、选页、源 spill 验证、正文读取与校验、最终复核、IPC 返回、失败原因完成、store 提交及 React commit/下一绘制机会。渲染与主进程分别算本地 duration，以 trace 关联，不能直接相减不同进程的单调时钟。

指标：总历史事件/流数量、页消息数、正文依赖事件数、扫描字节数、SQL 次数/行数、Worker 创建与排队耗时、缓存路径（ready/旧权威/cold/invalidated）、重试次数、后台任务类型、主线程 event-loop delay、RSS。构建分片补充不含正文的会话关联标记与触发来源。会话关联使用进程内匿名标识，不记录标题、路径、正文、token 或原始载荷；日志经过现有脱敏机制。

矩阵固定为 1千/1万/10万事件，另独立变化流数量、正文总字节数、单条巨型消息、spill 数量；页大小固定 20。分别测试 ready、无缓存、损坏、源持续变化、后台维护开/关、进程首次访问与重复访问。每格至少 30 次，报告 p50/p95/max 和失败率，不将无关冷启动混入热缓存统计。记录提交、Electron 版本、硬件、库大小、系统文件缓存条件。真实库只用隔离副本；保持原库不变。

查询计划覆盖页游标、消息 ID 来源定位、源身份、构建待办扫描。先以 EXPLAIN QUERY PLAN 和行数证明访问范围，再决定是否添加索引；不凭猜测提前增加索引。

## 3. 模型与不变量【机｜人工可跳过】

### 3.1 必须维持的性质

- **INV-1 权威性：** 正文来自现有已批准的权威源；旧数据只在当前证明成立时可读。缓存缺失不意味着空正文。
- **INV-2 一页一致：** 骨架、正文、游标属于同一可验证源状态。异步读取前捕获身份，结束后校验；变化则丢弃结果，不能拼接新旧版本。
- **INV-3 有界读取：** 就绪首屏不遍历全会话流列表、缓存或历史；冷首屏不等待整会话缓存发布。成本按本页正文及完整依赖计算，单条巨型正文不承诺固定毫秒。
- **INV-4 生命周期：** 删除、代次变化、切库、编辑、压缩或恢复后的旧任务不能发布到新身份。复用现有 lease、generation、epoch 与 publish fence。
- **INV-5 隔离：** 切换后旧请求不得覆盖新会话；撤销一个等待者不杀掉其他读取者共享的构建。
- **INV-6 可恢复：** 新缓存未完整发布时不能作为 ready 使用；损坏可重建，原始历史和必要源 spill 不因缓存发布被删除。

### 3.2 所有权与生命周期

| 对象 | 唯一 writer / 提交点 | 失效与恢复 |
| --- | --- | --- |
| 原始对话与消息骨架 | 现有持久化写入口及原事务 | 继续遵循现有重构方案，不增第二写者 |
| 新正文分块及定位目录 | 现有投影构建 owner；源 fence 成功后的 manifest 发布 | 未发布块不可读，重启清理孤块/续建；失败不标记完成 |
| 来源定位及覆盖证明 | 同一投影 owner，绑定精确源身份 | 证明缺失转冷读取，不能自行宣称覆盖 |
| 前台读取状态 | 单次 query 调用，最终复核为返回点 | 失效有界重试；不改变持久化权威状态 |
| 后台优先级与等待者 | 现有 supervisor | 关闭/切库时按既有 stop/quiesce 屏障退出 |

## 4. 读取设计【机｜人工可跳过】

D-1=A 已批准新增可重建分页正文存储方向；以下为待 P2 验证的候选设计，数据库迁移与生产切换仍须满足各自门禁。

### 4.1 热路径：可寻址的不可变正文块

采用“manifest + 有大小上限的正文块 + messageId 定位目录”，替代一次选页扫描整份 JSON。目录定位到块与块内记录，记录包含会话代次、规格版本、源身份、长度与摘要；读取本页涉及的块并独立验证。单条超大正文独立成块，不强行切碎其显示语义。块上限由测量确定并固化为内部常量，不增加用户设置。

构建时验证全量目录覆盖、ID 唯一性与源一致性；发布后读取只依赖已验证 manifest 与本页块的摘要。不能简单对旧整体摘要文件 seek 后省略校验。文件访问继续走现有路径防护；源 spill 的真实性校验保留，优化必须用本页依赖清单替代全会话扫描，无法证明依赖完整时不得跳过。

选页依旧使用 `beforeSequence` 和现有排序，数据返回结构保持 `ChatMessagePage`。正文目录不决定可见消息顺序、状态或分页边界。已变更的消息必须重新生成对应派生产物，旧目录不得跨源身份复用。

### 4.2 冷路径：按消息依赖读取，而非截取最近事件

先在现有事务封装内选择消息骨架、游标和源身份，再按目标 ID 定位完整事件依赖，交现有归约语义生成正文，最后重新核对源身份与页面。定位记录已经完整时，页面读取不等待正文块缓存发布；若旧会话尚无完整定位记录，首次回填行为由 D-3 决定，不能用未完成的地图返回页面。

来源定位必须覆盖 accepted-input、assistant 分段/终态、编辑与替换、工具结果、压缩快照、恢复及 spill。一个消息可能跨多条事件或整个 invocation；不能用“最后 N 条事件”近似。

**定位验证结果（P2-02，2026-10-27）：** 正文块自身可按页读取，但现有 turn/request 索引不能覆盖后续 invocation 对旧消息 ID 的 compaction upsert；全量 source identity 还会枚举所有 stream。未建立索引的旧会话没有有界冷定位路径。因此本节的“冷页只读依赖”还未成立，P3 不得开始。

**待决方案 A 的候选契约：** 已完整索引的会话按骨架页中的 message ID 批量查询来源定位记录，再读取相应 History 事件与本页 spill；压缩快照替换该 ID 的来源，assistant response chunk 累加到当前 assistant 来源。定位记录只保存事件坐标和依赖类型，不复制正文。事件、定位记录和会话来源修订号在同一 SQLite 事务中提交。对未索引旧会话，后台全历史回填完成前不能把部分地图当完整证明；首屏可能等待回填，但不能在主线程扫描。

来源修订号需由数据库事务内的 History 事件 insert/update/delete、stream owner/schema 元数据变更和消息正文/身份变更共同推进。manifest 捕获 generation、消息 revision、History watermark 与该修订号；source identity 热读不再序列化全部 stream IDs。每次异步正文读取后仍在同一查询契约下复核这些常量级版本事实。未获 D-3=A 前，此段只作为候选规格，不实施。

### 4.3 源身份与复核

先消除同一次无异步间隔中的重复快照读取，不跨异步间隔复用未复核身份。保留“选页—异步正文—最终复核”两阶段。

将全流列表身份改成固定成本版本戳只能在覆盖所有写路径后实施：append、编辑、删除、导入、恢复、压缩、旧数据回填、stream owner/schema 变化、切库均须使相关身份变化。P2-01/02 已证明当前 message_revision 与 watermark 不覆盖所有这些路径，也未证明 stream IDs 的固定成本替代。缺少任一入口的版本更新时，继续保留原检查；新增版本字段需通过 D-3 与 P2 规格门禁。用测试注入每种写入，验证旧快照均被拒绝。

每次页请求最多重试 1 次；再变化使用现有错误通路返回，不返回混合页、不无限重建。具体错误码沿用现有可达分支，若不足，在实施前定义稳定内部错误并核对调用方，不顺带扩展 IPC。

### 4.4 调度与取消

复用 supervisor 的合并、lease、checkpoint、stop/quiesce。前台目标页请求优先于后台整会话维护；在分片边界让出资源，不声称可抢占正在执行的同步 chunk。记录单 chunk 超预算，缩小输入字节/事件数；巨型事件用独立 Worker 处理并保留取消/退出屏障。

并发预算初始保持单个重构建任务，禁止因 A→B→C 快速切换同时启动三个整会话构建。前台与后台读取也受总 Worker/内存预算约束，避免“各自并发 1”实际堆叠。后台不得长期饿死，使用等待年龄晋升；具体时间常量由 P0 测量确定。

当前 IPC 不提供端到端 AbortSignal，本轮不假装渲染取消已经终止主进程工作。先用会话与显示 generation 屏障拒绝迟到结果，内部等待者释放与共享任务解绑；若需要跨 IPC 取消，另立契约决策，不偷偷增加接口。
