## 2. 三项隔离复现

在仓库根运行以下整段。使用已有 test helper，但不是新增产品测试文件；只构造内存库。断言描述的是**当前差异**，修复后应改为目标行为回归，而不是继续要求错误行为存在。

```bash
node --import tsx --input-type=module <<'JS'
import assert from 'node:assert/strict'
import { createMemoryAppDb } from './electron/database/testHelpers.ts'
import { createSession, appendMessage, getMessages, createPersistedTurn, hasActiveTurn } from './electron/database/operations.ts'
import { getDbConnection } from './electron/database/sqliteStore.ts'
import { SqliteAgentHistory } from './electron/runtime/sqliteAgentHistory.ts'
import { computeLegacyProjectionDigest } from './electron/runtime/sessionProjectionRejection.ts'
import { certifyCanonicalSessionApiRead } from './electron/sessionStorage/certification.ts'
import { enableCanonicalSessionWriteAuthority } from './electron/runtime/sessionContentWriteAuthority.ts'
import { markSessionMessageContentWriteStopped } from './electron/sessionStorage/maintenance.ts'

const db = createMemoryAppDb()
try {
  const session = createSession(db, { name: 'storage audit isolated memory fixture' })
  appendMessage(db, { id: 'audit-u', sessionId: session.id, role: 'user', content: 'question', timestamp: 1, status: 'sent' })
  appendMessage(db, { id: 'audit-a', sessionId: session.id, role: 'assistant', content: 'answer', timestamp: 2, status: 'completed' })
  const conn = getDbConnection(db)
  const history = new SqliteAgentHistory(conn, 1, Date.now, session.id)
  const base = [
    { id: 'audit-u', role: 'user', content: 'question', timestamp: 1 },
    { id: 'audit-a', role: 'assistant', content: 'answer', timestamp: 2 }
  ]
  await history.appendBatch([{
    invocationId: 'audit-i', turnId: 'audit-t', sequence: 1, schemaVersion: 1,
    eventId: 'audit-e', idempotencyKey: 'audit-e', kind: 'invocation-context-committed',
    payload: { messages: base }
  }], 0)

  const verified = history.readCanonicalSessionTranscript(session.id, base)
  assert.equal(verified.kind, 'matched')
  assert.equal(history.writeCanonicalSessionCache({ ...verified, cacheKey: 'transcript', value: JSON.stringify(verified.messages) }), true)
  const enriched = [base[0], { ...base[1], toolCalls: [] }]
  const full = history.readCanonicalSessionTranscript(session.id, enriched)
  const cached = history.readCanonicalSessionTranscriptWithCache(session.id, 'transcript', enriched)
  assert.deepEqual(full, { kind: 'unavailable', reason: 'legacy-mismatch' })
  assert.equal(cached.kind, 'matched')
  console.log(JSON.stringify({ probe: 'same-input-full-vs-cache', full, cached: cached.kind }))

  const rows = getMessages(db, session.id)
  const statusOnlyChange = rows.map((message) => message.id === 'audit-a' ? { ...message, status: 'failed' } : message)
  const selectComparedFields = (messages) => messages.map(({ id, role, content, timestamp }) => ({ id, role, content, timestamp }))
  assert.deepEqual(selectComparedFields(rows), selectComparedFields(statusOnlyChange))
  assert.notEqual(computeLegacyProjectionDigest(rows), computeLegacyProjectionDigest(statusOnlyChange))
  console.log(JSON.stringify({ probe: 'digest-scope', fourFieldsUnchanged: true, digestChanged: true }))

  assert.equal(certifyCanonicalSessionApiRead(db, session.id).status, 'eligible')
  assert.equal(enableCanonicalSessionWriteAuthority(db, session.id).status, 'enabled')
  createPersistedTurn(db, {
    turnId: 'audit-terminal-t', requestId: 'audit-r', sessionId: session.id,
    assistantMessageId: 'audit-a', userMessageId: 'audit-u', state: 'terminal', outcome: 'completed'
  })
  assert.equal(hasActiveTurn(db, session.id), false)
  const withTerminal = markSessionMessageContentWriteStopped(db, session.id)
  assert.equal(withTerminal, false)
  // 只删除此内存夹具的 turn，证明其为决定性输入。
  conn.prepare('DELETE FROM turns WHERE turn_id=?').run('audit-terminal-t')
  const withoutTerminal = markSessionMessageContentWriteStopped(db, session.id)
  assert.equal(withoutTerminal, true)
  console.log(JSON.stringify({ probe: 'cleanup-turn-state', persistedState: 'terminal', persistedOutcome: 'completed',
    hasActiveTurn: false, writeStoppedWithTerminal: withTerminal, writeStoppedWithoutTerminal: withoutTerminal }))
} finally {
  db.close()
}
JS
```

本次结果：exit 0，三项断言通过。

```json
{"probe":"same-input-full-vs-cache","full":{"kind":"unavailable","reason":"legacy-mismatch"},"cached":"matched"}
{"probe":"digest-scope","fourFieldsUnchanged":true,"digestChanged":true}
{"probe":"cleanup-turn-state","persistedState":"terminal","persistedOutcome":"completed","hasActiveTurn":false,"writeStoppedWithTerminal":false,"writeStoppedWithoutTerminal":true}
```

- **R-1**：全量比较保留可选 toolCalls/toolUse，缓存接口规整时删除两者。生产 `readCanonicalSessionTranscriptWithCache` 调用目前只传前两个参数，尚未找到触发此 rich-input 差异的生产调用，不能据此认定用户展示故障。
- **R-2**：负缓存 digest hash 整个 Message，实际 L2 生产比较先规整为四字段。后果是过宽失效/重验，不能称为错误放行。
- **R-3**：清理 SQL 使用 outcome 风格词判断 `turns.state`，而规范持久 turn 使用 terminal 状态和独立 outcome。这是已通过清理入口复现的状态判定缺陷；不代表真实用户已执行过清理。MessageStatus 不包含 interrupted，中断映射 failed，清理展示终态列表没有漏此合法枚举。

## 5. 待验证风险与已有行为

1. `sessionProjectionRevalidationQueue.ts` 使用进程 WeakMap；drain 只消费内存队列，startup interval 不从持久 rejection 回填；metadata 未变的 rejection 读取返回 hit，未必重新 enqueue。重启后到期拒绝是否最终可重试为**静态可达性风险，尚未实测**。目标应有按持久 due 索引的有界重试，内存队列只作唤醒优化。
2. 编辑 canonical-backed 正文没有提交 Hosted transcript，而 handoff 的 checkpoint 分支与 chat 投影来源不同。不同 scope 的行为已经查明，但完整产品语义、各渠道与接纳版本行为仍待场景对照；本轮不擅自统一。
3. JSONL 手动压缩/重放仍包含生产语义；覆盖表不完整时不能声称“文件可随时删除并全部重建”。
4. 原启动优化执行计划记载用户已选择：旧 ledger 缺失仅阻断依赖该 ledger 的功能，普通 canonical 历史仍可读。该行为是兼容边界，不在本轮重新决策。
5. `schema.ts` 当前 `DB_SCHEMA_VERSION=102`，旧大方案中某些 schema/阶段计数属于历史记录。新迁移必须从实施时的真实基线选择下一版本，不能照旧文档写死编号。

## 6. 方案独立评审核销

本轮由三个独立审阅方向核对事实权威、状态/恢复、迁移/闸门。以下为文档修订闭合，不代表产品实现已经修复。

| 评审问题 | 本轮处理与证据 |
|---|---|
| spill 准备先于 fence，留下引用提交前回收窗口 | 方案 §3.3 改为保护区内准备 spill，并持续到引用提交/回滚；与既有 location → spill fence → SQLite 顺序核对 |
