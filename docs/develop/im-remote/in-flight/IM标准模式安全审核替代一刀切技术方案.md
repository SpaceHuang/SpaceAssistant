# IM 标准模式：将一刀切禁止改为安全审核的技术方案

> 状态：方向已决策、2026-10-29 评审后修订的技术方案草案；D-01～D-05 选 A，D-06 选 B，D-07 选 A（2026-10-28）。具体界面及尚未验证的执行边界仍需按本文门禁处理；本文不表示实现或配置切换已经完成。代码事实基线：`990d1e2e7a57f14259e2977f4285f4649cdc11f9`，核查日期 2026-10-28。面向微信、飞书交互式远程会话；不改变定时任务。

## 第 0 层：需要负责人决策【人必读】

**一句话**：用户在手机上请求操作电脑时，普通命令、文件和网页目前可能因为来自远程而直接被拒绝；本方案将可核实的具体操作交给安全审核 Agent，并保留敏感操作的人工确认与无法核实目标时的阻止。

**只有 3 分钟的话**：先看下方已确定的七项选择；目录外文件、命令和网页为主要体验变化。新版本全部能力通过验收后，标准模式用户升级时自动切换；验收未完成前保持现状。

安全审核 Agent 是独立检查具体操作与用户请求是否相符的程序；它可能批准、拒绝，或在证据不足时转人工，不保证每次都通过。下列决策均可通过恢复旧策略版本回退，但已经执行的文件修改、命令和发送无法靠回退撤销。当前依据为代码和现有测试，尚无真实手机端成功率或审核误判率数据。

### D-01 目录外普通文件【人必读】

用户可能只知道“项目旁的报告”，不知道电脑完整路径。现在目录外普通文件的读取和修改直接被拒绝。决定：A，让安全审核 Agent 根据明确的文件、用途和修改内容逐次判断；B，继续禁止。A 可减少手机输入和切换目录的负担，但可能读取或修改审核误判的文件；敏感文件仍需真人确认，无法确定目标时不执行。B 风险面不扩张，但普通任务仍被拦截。已决定 A。下钻：INV-01、INV-02、AC-01、AC-02。

### D-02 电脑命令【人必读】

用户远程要求查看项目状态或运行检查时，现在所有电脑命令都被禁止。决定：A，对能核实完整命令及运行材料的调用逐次交安全审核 Agent，遇到敏感操作或无法可靠分析的情况要求真人确认或阻止；B，继续全部禁止。A 可以完成常见 Git 和检查任务，但命令可能间接运行项目脚本或访问网络，审核不能保证识别所有影响；B 避免扩大命令权限，但这些任务仍无法执行。已决定 A。下钻：INV-03、AC-03、AC-08。

### D-03 网页查询与操作【人必读】

远程浏览器默认关闭，用户可能无法让助手查阅网页；开启后网页也可能处于个人登录状态。决定：A，标准模式自动升级后，让用户明确选择是否开启远程浏览器；同意开启后普通查询按标准模式审核，高影响操作仍需真人确认；B，保持远程浏览器原配置，用户自行到设置中开启。A 更容易完成网页查询，但可能接触登录态和误导性网页，也需要设计清楚的选择界面；B 保持现有设置，查资料前可能还要操作电脑。已决定 A；在终端用户未同意开启时保持关闭，已有关闭配置不得静默改变。后续可以关闭，但无法撤销已经发生的网页操作。下钻：INV-04、AC-04。

### D-04 微信附件【人必读】

用户可能要求把电脑上工作目录之外的一份文件发到自己的微信。目前即使文件明确也被禁止。决定：A，允许安全审核 Agent 审查明确的文件、内容和收件人，再决定能否发送；敏感内容仍需真人确认，文件或收件人无法核实时阻止；B，继续限制附件必须位于工作目录内。A 减少复制文件的负担，但误判可能把私人资料发到聊天；B 限制更强且使用麻烦。已决定 A。下钻：INV-05、AC-05。

### D-05 联网脚本【人必读】

远程脚本只要出现联网行为就被禁止，可能影响下载资料和访问公开接口。决定：A，仅将目标和代码能被可靠核实的联网脚本逐次交审核，动态行为和敏感操作仍须真人确认或阻止；B，继续禁止联网脚本。A 能完成更多任务，但脚本可间接执行代码或传出数据，审核存在误判；B 更保守。已决定 A，但它依赖完整事实和执行绑定能力经过验证；验证失败时维持 B。下钻：INV-06、AC-06。

### D-06 已有用户的切换方式【人必读】

以上变化会扩大远程助手能尝试的操作。决定：A，已有用户在看到具体变化并明确同意后才切换，新安装也先沿用当前行为；B，升级后将标准模式用户自动切换。A 避免用户没有察觉地扩大权限，但新体验需要主动选择；B 更容易用上新能力，但升级可能改变用户原本依赖的限制。已决定 B，在新版本全部能力通过验收并正式发布后，标准模式自动切换；届时新安装也采用新标准模式。验收未完成前继续使用旧版本。主动切回旧版本后，重启或升级同系列程序不会自动切回新版本；要再次启用需明确操作。已经执行的操作不能靠回退撤销。下钻：INV-07、AC-07a、AC-07b。

### D-07 敏感工作目录【人必读】

用户可以为工作目录标记敏感；当前远程无法切换到这类目录，切换还会影响同一会话后续操作。决定：A，本次保持禁止；B，允许用户逐次确认后切换，并重新设计后续操作的权限范围。A 本次不解决这类目录的远程访问，但边界清晰；B 更灵活，也可能让后续请求获得超出用户当次意图的访问范围，需要另行设计。已决定 A。下钻：范围与 AC-09。

**不需要负责人决定**：核对真实调用路径、事实完整性、审批绑定、失效处理、竞态测试和旧版本兼容由实现与评审负责；不能用“交给审核 Agent”替代这些工作。上述方向已由负责人决定；涉及新界面时须另出界面归属卡并获批，未验证的执行边界仍须通过验收。

## 第 1 层：概要【人机共读】

### 1. 验收边界和范围【人机共读】

**可观察目标**：标准模式升级并自动切换后，微信和飞书中的普通 Git 查询、目录外指定文件读写、已启用的网页查询，能对具体调用进入安全审核并在审核通过后执行；审核拒绝或事实不完整时无副作用。微信目录外附件和可分析的联网脚本分别以 D-04、D-05 为条件。

本地自动化可验证规则命中、事实、审核材料、执行绑定、失效和模拟渠道；真实飞书/微信、手机交互、浏览器登录态、系统 Shell 及外部网络的端到端体验需要真实环境验收。本文不声称已有真机结果。新行为上线前须同时完成两类验收；真实环境不可用时只交付代码和自动化证据，不宣称上线验收完成。

不做：改变 automation；放宽身份入口或 MCP 工具调用策略；允许微信主动发送；关闭敏感路径/高危操作人审；新增通用目录授权；未经用户明确选择改变远程浏览器配置；允许敏感目录切换；新增集中预授权（与 [IM 指令权限预检方案](./IM指令权限预检与集中审批技术方案.md) 独立）。方案只讨论逐调用审批，不能把另一方案的预检结果当作本方案的执行许可。

### 2. 现状与选择【人机共读】

现行 IM 策略在调用入口形成事实、匹配共享策略，命中硬拒绝时不会交审核 Agent；通过审核后还要经过执行前的材料与许可校验。目录外读写、远程 Shell 和部分附件被硬拒绝；浏览器被关闭开关及执行器共同约束；脚本联网另有硬拒绝。工作目录可按已配置名称、别名切换，不能替代临时目录外访问（F-01～F-08）。

选择**按操作、事实和调用内容审查**：普通且事实足够的候选交 Agent；人审底线优先；材料不可核实时不签发执行许可。排除两个方案：①直接删除所有硬拒绝并默认放行，会绕过审核和原有安全下界；②扩大工作目录或授予 Shell 通配权限，会把一次意图扩大成后续权限。已有 `allowRemoteSessions=false` 是明确配置边界，仅在用户明确选择开启后修改；关闭时策略和执行器均继续拒绝。

## 第 2 层：规格【机｜人工可跳过】

### 4. 术语与不变量【机｜人工可跳过】

术语：**事实**为宿主观察到的目标、内容、身份、覆盖程度；**策略**决定拒绝、人审或 Agent 审核；**审核回执**仅针对一次具体调用；**执行许可**是执行器使用的调用绑定材料；**最终核验**只核对已批准身份、对象、授权代次、许可与执行材料，不重新判断业务风险。政策变更后的重新决策属于 policy 阶段，不叫最终核验。

| ID | 不变量及对应验收 |
|---|---|
| INV-01 | 用户任务意图、渠道身份和每个实际目标由宿主绑定；Agent 的用途文字不是授权证据。AC-01、02、05、08。 |
| INV-02 | 普通路径可以进入审核；敏感/系统路径、未知对象和不支持目标不得因目录外规则变更降低保护。最终核验失败时执行器未调用。AC-01、02、09。 |
| INV-03 | Shell 审核只覆盖完整命令、实际 cwd、shell/环境、超时和计划；不推导为前缀或全局权限。非可证明的间接影响不能标成“已完整分析”。AC-03、08。 |
| INV-04 | 浏览器全局及远程关闭开关仍有效；网址、当前页面和动作事实变化不得复用批准；高危动作保留真人底线。AC-04、08。 |
| INV-05 | 附件读取与向接收者发送为不同决策；路径、文件身份、内容检查、接收者、渠道及授权代次均绑定；未知事实不发送。AC-05、08。 |
| INV-06 | 联网脚本必须绑定代码、参数、运行环境及可观察网络事实；分析不完整不能由模型的解释补齐。AC-06、08。 |
| INV-07 | 只有固定能力集合全部通过验收并正式发布后，标准模式升级才自动采用该不可变版本；其他档位、显式限制和浏览器开关不因迁移放宽；主动回退后禁止再次自动迁回同一行为版本，直至明确重新启用；旧版本行为冻结。AC-07a、07b。 |
| INV-08 | Agent 不可用、超时、取消、拒绝、许可缺失、身份/对象/策略代次变化时不能执行旧批准；重放不能产生第二次副作用。AC-08。 |

### 5. 规则裁决矩阵【机｜人工可跳过】

以下按已确定的 D 项给出目标规格；尚未通过相应验收的能力维持旧版限制。新策略版本内按细分事实新增稳定 rule ID，旧 ID、旧 match 和原动作由旧版本冻结，不能直接修改共享默认数组造成旧版本漂移。安全裁决顺序为：身份及执行前置约束 → 聚合全部命中的有效拒绝（包括用户显式 deny 与配置条件拒绝）并终止 → 真人确认底线 → 审核候选 → 默认兜底。约束与事实可先收集，但不能先返回人审而跳过拒绝聚合；命中拒绝时不发起审批、不调用 executor/dispatch。新版本仅精确替换本方案已批准放宽的旧拒绝，其他拒绝仍优先于人审和审核；以引擎与 trace 的可执行测试验证，不依赖数组顺序。

| 现规则/入口 | 新版本目标 | 边界 |
|---|---|---|

| `remote-write-scope-unknown-deny` | 保留拒绝，诊断区分范围分类失败与探测失败；确定事实后新调用重新评估。 | unknown 不是 outside；禁止用 Agent 推断代替宿主事实。 |

### 6. 事实、契约与状态所有权【机｜人工可跳过】

**事实契约**：每个候选的宿主事实至少包含 `invocationId`、工具名、原始参数摘要、来源 lane、认证用户/会话/授权代次、策略版本与依赖指纹、目标与覆盖程度；材料由宿主从实际调用计算，不采信模型的自报用途作为事实。具体补充：

| 候选 | 审核材料 | 不可审核条件 |
|---|---|---|
| 文件读取 | 规范化真实目标、类型、身份、读取范围（单文件或直接目录项）、与用户任务的关联 | 目标无法解析、特殊对象、范围不明、目录递归覆盖不足。 |
| 文件写入 | 真实目标、类型、父目录/现存文件身份、完整新内容或可验证差异、覆盖/新建语义 | 路径/身份探测失败、目标非支持类型、内容不完整或无法绑定。 |
| Shell | 完整命令、实际 cwd、shell、有效超时、环境与准备后执行计划摘要、解析覆盖和风险信号 | 不能绑定执行计划；解析不完整或存在动态/间接行为时不得称作安全：转真人确认，若材料仍无法绑定则拒绝。 |
| 浏览器 | 配置、动作、目标 URL、当前页面/会话身份、危险评估、提交参数 | 无法识别目标、页面变化或高危动作缺真人批准；关闭开关仍拒绝。 |
| 微信附件 | 真实文件身份及内容检查覆盖、实际上传内容绑定、接收者与会话、原始发送参数 | 内容/对象/接收者不明，或不能保证实际上传字节与获批材料一致。 |
| 联网脚本 | 完整代码、解释器、参数、cwd、超时、环境摘要、网络目标/方法及静态分析覆盖 | 无法绑定执行材料；网络目的或动态行为无法可靠判断时转真人或拒绝。 |

审核结果仅允许 `approve`、`deny`、`needs-human`；Agent 不可用、超时、无效结果按现有降级流程进入真人确认，若渠道无法完成确认则拒绝，不得静默批准。事实不完整且不能绑定执行材料时，即使真人同意也不执行；引导生成可核实的新调用。每次批准只覆盖一次调用，不新增跨调用缓存或可信前缀。

| 状态 | 唯一写入者 / 提交点 | 失效和恢复 |
|---|---|---|
| IM 策略快照、版本与迁移抑制 | 策略存储是唯一 writer；回退或显式重新启用时，版本、revision、抑制字段和审计在同一事务提交。普通设置保存保留抑制字段。 | 读取异常、抑制字段无效或未知版本时不自动迁移；重启以提交的快照为准，不回滚数据库文件。 |
| 事实快照 | gate 的宿主事实生产器为调用创建；不写策略结论。 | 同一调用材料变化或重新准备后生成新事实；旧审核不能沿用。 |
| 决策与审核回执 | 共享 Policy Engine 给稳定 rule ID/trace；确认通道针对调用记录回执。 | 拒绝、取消、超时无许可；策略依赖变化重新决策，不能复用旧回执。 |
| 执行许可 | 宿主许可构造器在批准后绑定调用与事实，执行器消费。 | 许可缺失、已消费、身份/目标/代次不符则拒绝；最终核验不重算风险。 |
| 异步待办及恢复 | 现有延迟审批存储和恢复协调器负责持久化、领取与恢复。 | 重启、重复投递沿用现有身份及任务栅栏；确认是否支持新增工具材料须以集成测试证明，不支持时禁止延期执行。 |

**并发与失败**：审核期间修改文件、切换目录、撤销用户、改变策略、浏览器跳页或替换附件都使旧回执失效。执行前通过宿主重新观察事实及 policy recheck 决定是否要重新审核，随后 final-check 只校验许可和实际执行材料。调用被取消时阻止尚未 dispatch 的调用；已经 dispatch 的外部副作用按现有执行结果记录，不声称可撤销。重启后不能重放尚未证明未执行的副作用；结果未知时标记未知并要求用户核对。

**稳定失败分类**：复用已有错误及 trace；新增边界需定义 `IM_REVIEW_FACTS_INCOMPLETE`（environment，未 dispatch）、`IM_REVIEW_BINDING_CHANGED`（mechanism，未 dispatch）、`IM_REVIEW_UNAVAILABLE`（dependency，未 dispatch）、`IM_REVIEW_POLICY_CHANGED`（policy，旧回执无效）及 `IM_REVIEW_RESULT_UNKNOWN`（结果不明，不自动重试）。具体 case ID 在实现时一对一登记和测试；不记录命令输出、文件内容、密钥或消息正文到普通日志。

### 7. 按工具的执行边界【机｜人工可跳过】

1. **读写**：沿用宿主路径探测和读写 permit；扩展远程目录外许可的可达路径，不把 desktop 专用的目录 grant 当成 IM grant。测试符号链接替换、父目录替换、文件替换、目标缺失和特殊文件。目录项快照和递归子树不同，不得用根目录身份保证子项均安全。
2. **Shell**：前置预检、策略和实际执行均检查同一准备后计划，审核材料中必须说明分析覆盖。审查 Agent 对 `git status` 的批准只绑定这一命令和环境；`git push`、hook 与外部 helper 不作为无副作用的 Git 查询。进程不是沙箱，审核是风险判断而非系统级访问控制；未能绑定计划或恢复状态时拒绝。
3. **浏览器**：关闭开关仍由 policy 和 executor 同时约束；开启后验证 `browser-navigate-ask-remote`、低影响动作和高危人审实际优先级。导航后的重定向、新页面、已登录账户及页面提示注入要进入风险模型；如果执行器无法核实获批动作目标，则该动作不自动执行。
4. **附件**：目前执行器还有目录外检查，必须有能覆盖实际上传字节的宿主许可、内容检查和身份校验后，才能改变该执行器；只改策略会导致功能仍失败。内容判断不完整按现有更严格出站策略处理；敏感内容仍真人确认，主动发送禁令不变。
5. **脚本**：复用现有脚本内容/参数/环境绑定，并增补可验证的网络目标与分析覆盖；不能仅依赖代码中出现的字面 URL 作完全网络约束。若不能证明实际执行材料或所需影响，维持现有拒绝。

### 9. 版本、迁移与回退【机｜人工可跳过】

本方案以新行为版本 `im-standard-v3` 为设计标识，具体版本名不得复用已发布版本。新增版本解析器和版本化底线；`im-v1.6`、`im-standard-v2` 使用各自冻结的规则快照，不能只将旧 resolver 继续指向会变的全局默认表。迁移前先建立基线对拍，覆盖 locked 规则、所有 lane、旧设置、禁用规则和用户覆盖；否则不得切换。列出并更新所有受支持版本白名单、运行时加载、提示快照、延迟审批恢复和版本校验；未知版本 fail closed，不能降级成较宽默认。

自动迁移算法：仅在下述发布门禁全部满足、包含已发布 v3 的程序升级启动时运行；未发布的开发或测试构建不得迁移或把 v3 设为新安装默认。启动时先完成旧版快照读取与可映射性校验；仅当当前 IM 套餐为 `standard`、原有显式限制能完整保留，且当前快照不存在阻止目标版本 v3 的有效回退抑制记录时，使用现有事务比较 revision，写入新版本及迁移来源、追加迁移审计；成功提交为完成标记。revision 冲突或进程在提交前退出时事务不提交，下次启动重新读取并重试；已为新版本时不再迁移。规则映射失败、快照无效或无法表达已有用户限制时不切换，保留旧快照并维持旧保护。`custom`、`strict`、`loose` 不自动转为新标准；正式发布后，新安装的标准模式初始化为已发布的新版本；发布前新安装使用旧版标准模式。升级自动迁移不代表终端用户同意开启远程浏览器：D-03 的选择独立进行，未明确同意前保留原开关。持久化模式变更若需要新字段，必须先完成具体格式审批。

**唯一激活门禁与固定集合**：`im-standard-v3` 唯一包含 §5 的目录外普通文件、Shell、浏览器、微信附件、联网脚本的全部目标行为，及表中明确保留的拒绝；发布后不得在同一版本改变规则集合或能力语义。阶段 A～E 均为未激活的开发/验证构建，只在隔离测试中加载候选规则；生产加载器与新安装初始化始终选择原有版本。A 完成而 B 未完成、或 B 完成但 D/E 任一验证失败时，v3 未发布、不得自动迁移，已有用户和新安装均加载原快照或原安装默认；测试中产生的临时 v3 状态不得进入生产。

正式发布阶段 F 的入口必须同时具备：A 的旧版本对拍与迁移 dry-run 通过；B～E 各项自动化及真实环境验收通过（AC-01～06、08、09）；D-03 界面及配置变更满足 §3 的审批门禁；版本化规则、floor、执行材料与决策依赖指纹对拍一致；安全注册表检查通过。缺少任一项则发布产物不得声明 v3 就绪，也不得运行迁移；不得以运行时未定义的能力开关拼出部分 v3。阶段 F 的发布产物构建流程是唯一的 v3 就绪声明者，发布时将固定规则集合与上述验收证据绑定；应用侧唯一迁移 writer 是启动迁移器，经现有策略存储事务提交版本、revision 和审计。新安装由现有初始化器在同一发布产物中选择 v3，不参与已有快照迁移。实施前应以测试证明两条写入路径互斥且无其他入口可提前激活。

若确需提前公开部分能力或某项无法验收，需要另行设计独立行为版本和对应迁移、回退及验收；本文不授权用部分规则集合发布 v3。对于已发布的 v3，重启或重新升级加载同一冻结集合；任何后续扩展使用新的行为版本，策略依赖变化使尚未执行的旧回执失效并重新决策。

回退实体为**单个 IM 域策略快照版本及其迁移抑制记录**。拟在同一快照的 `automaticMigrationSuppressedVersions` 字段保存行为版本 ID 的去重数组：字段缺失代表没有主动回退记录，回退 v3 时集合包含 `im-standard-v3`；字段非数组、成员非有效版本 ID 或读取失败时禁止自动迁移并记录稳定诊断，不把异常当作空集合。该字段是新持久化格式，须按 §3 获批后实施；在现有用户数据中它尚不存在。作用域为整个共享 IM 策略域，不按微信、飞书分别记录；本字段只影响自动迁移，不替代工具规则和用户覆盖。

**受控回退**：读取当前快照及 revision；在同一 `runInTransaction` 事务中比较 revision，写回用户指定的受支持旧行为版本、将 `im-standard-v3` 加入抑制集合、递增 revision 并追加回退审计，事务提交是唯一生效点。冲突、审计写入失败或崩溃导致事务回滚时版本及抑制记录均不生效；重启读取最后一次已提交快照，不得出现仅写回版本而丢失抑制记录。不得删除历史回执或用户覆盖；版本或策略依赖变化使尚未执行的旧回执失效，已执行副作用不回滚。

**启动与重新启用**：启动迁移器在上述同一事务中重新读取快照、版本和抑制集合，再判断目标版本；包含 `im-standard-v3` 时跳过 v3 自动迁移，不追加迁移审计。重启、同系列程序升级、revision 改变及无关配置保存均不得移除该标记；普通快照写入必须合并保留该字段，不允许客户端通过常规配置写入删除或伪造它。唯一例外是用户通过受控的显式重新启用 v3 动作，在同一事务比较 revision、重新校验 v3 发布门禁及限制映射、切换到 v3、从集合删除该版本并追加审计；失败或冲突全部回滚。再次回退则重新添加标记。该抑制精确针对 v3；未来其他行为版本的迁移策略须另行定义，不得将本条静默外推为对未来版本的批准。

旧版程序若不能识别新版本，禁止直接以旧二进制启动后静默放行；先切回旧版本，再降级。具体回退、重新启用 UI/接口须通过 §3 门禁；若旧程序可能丢弃该新字段，则在完成旧程序保留字段的兼容性验证前不得降级。
