# 文档写作指南：来源与维护附录

> **本文件服务于审计与修订。日常写作任务不需要加载本文** —— 读 [`document-writing-guide.md`](document-writing-guide.md) 正文即可。
> 分工见正文 §1：正文只放动作，本文件放出处、口径、案例与维护规则。

## 归纳口径

本指南来自 **2026-10-16 对 `docs/rules/` 这一层自身的清理实践**，加上 `docs-guide` §9.1 原有的"分层惯例"条目。它属"实践规则"：证据是**可复核的改动记录**，而不是抽样统计。

**连带改动**：技术方案篇 → 只留方案特有内容，篇头改为通用层指针；需求篇 → 引用由"第 1 篇"改"元指南 §8–§11"；`README.md` → 技术方案 / 需求 / 执行计划三行加注通用层；`docs-guide` §9.1 → 文件清单同步。

## 修订记录：§4.3 路由口径放宽（2026-10-16）

- **原口径**：跨文件路由只放在入口层，各篇之间**禁止互相路由**（唯一例外：专题篇指向通用层）——即收敛记录 2 的来源。
- **新口径**：**导航集中（入口层）、指针就地（正文）**。正文用到别篇规则时可直接写「判据见《X》§n」，约束三条：不做导读清单、不复制被指内容、单向不闭环；`-sources.md` 之间的追溯引用不受限制。
- **证据与理由**：① 使用者判断"禁止互相路由"过严——规则归属指针是执行者的正常需要；② 本轮实测：通用层迁出后，"需求篇的交互取值 → 交互判据"这类引用无法由"指向通用层"这一个例外覆盖，而把它全塞进 `README.md` 会让读者在正文里失去线索；③ 原判据要防的是 **N² 互链与隐藏导读**，不是规则指针本身——新口径保留前者、解除后者。
- **连带改动**：`README.md` 末行"两篇之间互不路由"改为"只留单向的规则归属指针"；元指南 §7 检查清单第 8、9 条措辞同步。
- **未改**：入口层导航唯一性（`README.md`）、`AGENTS.md` 只留一行指引、篇内路由鼓励。

## 局限

1. 依据是单项目的一次性清理实践，样本小；除案例 5 外，其余都是"改动可复核"而非"跨主题重复出现"。
2. 判据 A 在边界情形需判断（"怎么用"与"从哪来"常混在一句话里）；正文已给细化规则，但仍有解释空间。
3. 尚未做实测：让一个没参与本轮讨论的人（或 Agent）按本指南新写一篇指南，看是否还会出现薄厚不分、出处混入正文的问题。

## 维护规则

1. 新增条目先过判据 A：它是给执行者的动作，还是给维护者的信息？
2. 新增案例写进本文件"案例"一节并注明对应判据，**不要直接写进正文当论据**。
3. 与专题指南冲突时，先判"层归属错误"还是"规则写错"，再决定改哪一篇。
4. 本指南自身的修订同样留痕；迁移时旧位置留指针。
