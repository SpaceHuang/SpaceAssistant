# 技术方案写作指南

> **定位**：写**技术方案**（规格、验收、迁移、回滚）时读本篇。
> **通用层**：读者分层与人机分工、写作流程与门禁、人类决策层规则 R1–R8、通用自检定义在 [`document-writing-guide.md`](document-writing-guide.md) §8–§11（元指南）；本篇只写方案特有的写法，不重复。
> **篇内路由**：写方案正文 → §0–§1；规格层逐项自查 → §2；改稿 → §3；交人评审前 → 附录（通用自检见元指南 §11）。
> **来源与维护**：见 [`technical-plan-writing-guide-sources.md`](technical-plan-writing-guide-sources.md)（按需查阅，日常不必加载）。
> **一句话**：写作的目标不是表达设计，而是让别人得到**唯一行为**——**真人只审决策，机器审规格**。

## 0. 两条前提

1. **方案不是表达的载体，而是规格 + 决策记录 + 证据包。** 出现「原子 / 实时 / 幂等 / 永不 / 不丢」这类结果词时，同行必须给出机制与验证点；给不出，说明机制还没想清。
2. **写作顺序决定质量。** 「背景 → 目标 → 设计 → 步骤 → 验收」是**阅读顺序**，不是**论证顺序**。按阅读顺序写，就会在写"设计"时才第一次面对现状与状态转移，于是只能就地打补丁。`docs-guide` §3.6 已实测：6 份现状文档中 3 份因"先写后查"返工。

## 1. 读者分层（方案版）

三层读者的通用规则、第 0 层固定骨架、人机分工、读者标记、ID 体系的一般要求见元指南 §8；方案侧只需落定下列内容：

| 层 | 读者 | 本层放什么 |
|---|---|---|
| **第 0 层 决策层** | 决策人、负责人（不读代码、只看这一层） | 决策项 `D-*`：价值取舍、不可逆承诺、风险容忍（分工见元指南 §8.3） |
| **第 1 层 概要层** | 人机共读 | 方向、范围、主要风险与排除方案 |
| **第 2 层 规格层** | 实现者 / 评审 Agent | 不变量 `INV-*`、契约、状态与所有权、验收 `AC-*`、迁移与回滚 |
| 附录（证据 / 核销 / 未验证项） | 追溯与复核 | 事实 `F-*`、核销记录、待定项与未验证项 |

**ID 体系（方案侧）**：决策 `D-*`、不变量 `INV-*`、验收 `AC-*`、事实 `F-*` 各成一套，**互相引用而不互相复制**；真源唯一，第 0 层只指向、不重写；层间引用必须**可双向追溯**（"这个决策变了，哪些规格与验收随之失效"要答得上）。

**适用面（裁决条目）**：方案主体里需要人拍板的条目 —— 边界声明、技术选项、不可逆承诺、承重墙改动 —— 同样是**裁决条目**，按元指南 §10（R1–R8）写：只出现在第 0 层是不够的。

**界面改动（触发线）**：方案里出现界面语义（用户可查看 / 显示 / 面板 / 列表 / 展开 / 开关 / 入口 / 按钮 / 提示 / 状态展示）时，必须先拿到获批的**界面归属卡**（5 行，见[交互设计指南](interaction-design-guide.md) I8）；**未获批不得排入阶段**，也不接受"先实现、界面待评审"。

**需求外扩声明**：方案相对需求**新增的交付面**（新 UI、新 IPC、新持久化字段、新开关、新状态模型）必须逐条列出并注明来源条款；**来源条款不是决策项（或只是"推荐默认值"）时，先回去补需求决策，再排阶段**——"需求里一句话变成方案里一个阶段"是加戏的高发点。

## 2. 规格层（第 2 层）写作要求

写作流程、产出物（事实卡 / 模型卡 / 契约卡 / 场景矩阵 / 验收映射表）与门禁按元指南 §9 走；本节只写方案在规格层的逐项要求——均为评审高频项，逐条给出要求与反例症状：

| 内容 | 要求 | 反例症状 |
|---|---|---|
| 不变量 | 写"不可违反的性质"，每条被流程与测试引用 | 目标散落在各章，互相冲突 |
| 状态与所有权 | 每个状态**唯一 writer**、唯一提交点、唯一恢复者 | 一个字段承担四种职责（排序 / 新鲜度 / 缓存键 / 提交校验） |
| 契约 | 类型给形状、字段给归属层与缺省值、错误码稳定 | 只给类型名；期望值由被校验对象自己填充（自证） |
| 失败与恢复 | 枚举崩溃窗口，每个窗口给唯一恢复动作 | 只在 catch 里恢复却声称支持崩溃恢复 |
| 并发与原子性 | 给锁顺序、临界区、幂等键、可等待屏障 | 宣称"一个 action 原子更新两套状态" |
| 承诺配对 | 每个强断言同行给机制与验证点 | "原子 / 实时 / 不可变"只有形容词 |
| 验收 | 从目标正向推导；用例可达且可执行 | 规则永不命中，用例天然不可达；以"代码行数归零"当验收 |
| 迁移与阶段 | 迁移算法、事务边界、完成标记语义、精确回退实体；每阶段定义输入 / 输出 / 出口证据 / 可回退实体 | 把"幂等 CREATE TABLE"当版本迁移；跳过失败仍打完成标记；阶段不可独立回退 |
| 测试 | 按不变量与协议组织，含竞态 / 故障注入 / 对拍 | 测试跟着补丁走，全绿却不覆盖跨渠道不变量 |

配套纪律：**排除方案也要写**（选了什么、为什么排除另一个）；**不确定必须显式化**（写成"待定项 + 影响 + 谁拍板"，不要用"或 / 建议 / 视情况"糊过去）。

## 3. 修订纪律

1. 每轮修订先交**核销表**（上轮问题 → 本轮状态 → 证据），再审新风险。不要用"已补写"当关闭依据。
2. **同一处 / 同一概念被第二轮指出 → 停止局部修补，回退到模型层重写那一节。** 判据：如果修一处要跟着改三处无关章节，说明模型错了。
3. 修订要区分"改模型"与"改文字"；前者重新跑元指南 §9 的第 4 步（反例）与第 5 步（验收）。

## 4. 反模式 → 对应步骤

反模式本身是**结果**；下表把它挂到"哪一步没做"（步骤编号沿用元指南 §9），以便修复而不是记口号。

| 反模式 | 属于哪一步没做 | 典型例证 |
|---|---|---|
| 方案的"现状前提"与代码不符 | 第 1 步（事实） | 称"产物绑定原工作目录"，实现却会回退到当前工作目录 |
| 反复在相邻边界出同类问题 | 第 2 步（模型） | 问题不在某个 IPC 字段，而在"一致性模型未先于实现建立" |
| 一个词 / 一个字段多义，或留"二选一" | 第 3、4 步 | 一个版本号兼做排序、新鲜度、缓存键、提交校验 |
| 承诺超出可执行边界 | 第 4 步（承诺—机制配对） | 宣称"原子接管"，却无法与模块级状态共事务 |
| 验收不可达 / 不可判定 | 第 5 步 | 阶段声称完成的 AC 依赖下一阶段 |
| 人类层看不懂 / 看不完 | 元指南 §10（R1–R8） | 决策项写 `outbound`；只给编号需翻详情；写成只有调研过才看得懂的命题 |
| 规格与进度混装、基线漂移 | 执行计划指南 §1 | 方案文档内嵌任务复选框与状态维护约定 |

## 附录 提交评审前自检清单（方案特有项）

通用层八条（第 0 层三问、事实与复现命令、承诺配对、未验证项、裁决条目已过 R7、R8 的"推荐默认值"禁用清单）见元指南 §11，本清单不重复。

1. 模型卡：不变量、状态所有权、销毁与恢复路径完整。
2. 契约：文档内闭合，术语一名一义，无"二选一"。
3. 验收：每条 AC 有可达用例；竞态 / 崩溃 / 迟到 / 重复已覆盖。
4. 迁移与阶段：算法、事务边界、完成标记语义、回退实体齐备；每阶段可独立编译、回退、验收。
5. 排除方案已写明：选了什么、为什么排除另一个。
6. 待定项与未验证项已显式化（影响 + 拍板人）。
7. 进度与任务清单已出方案：方案内不出现复选框与状态维护约定。
8. 涉及界面的改动已附**获批的界面归属卡**（《交互设计指南》I8）；未获批项没有排进阶段。
9. **需求外扩声明**已逐条列出（新 UI / IPC / 持久化字段 / 开关 / 状态模型），且每条来源都是决策项。
