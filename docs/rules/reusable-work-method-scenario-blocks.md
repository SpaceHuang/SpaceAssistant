# 可复用工作方法场景块

## 用途

本文是日常工作版，供 Agent 和团队按任务挑选方法。任务开始时选一个主场景块，必要时叠加一个风险块，并按任务范围裁剪。背景、项目状态和来源材料见配套的[来源与维护附录](reusable-work-method-scenario-blocks-sources.md)。

## 场景块 1：从故障现象到根因修复

**适用条件**：有异常会话、日志、失败测试、线上现象或明确的故障归因。

**SOP**

1. 固定提交、工作树状态、数据样本、复现命令和影响路径。
2. 把现象拆成可观察事实，沿调用链核对输入、转换、持久化和输出。
3. 寻找能精确解释现象的因果路径，并尝试构造反例或隔离复现。
4. 区分确定根因与未证实假设；强证据推翻原归因时，先修正诊断和优先级。
5. 用命中根因的最小回归测试锁定缺陷，再按端到端契约修复。
6. 检查相邻入口及失败、取消、重试等终态是否共享同一缺陷。
7. 报告复现、修复和验证证据，并列出未验证的环境边界。

**判断逻辑**：具体因果链和可复现证据优先于直觉解释。观测性建设不能替代已知根因的修复。执行事实与展示或脱敏文本应分层，避免错误输出改变对执行结果的判断。

**禁忌**：确定根因已有证据时仍只扩大日志；用“命令本应有输出”等启发式判断通用工具失败；只看结果文案，不核对状态码、错误类别和持久化结果。

**经验**：先用目标输入稳定复现；按“输入 → 执行 → 转换 → 持久化 → 展示/调用方”逐段核对；测试断言具体触发条件，不只断言结果非空。

## 场景块 2：需求 / 技术方案准入评审

**适用条件**：实现前的需求、架构、迁移、异步流程、恢复协议或安全方案评审。

**SOP**

1. 从用户目标写出可观测结果，区分本地动作成功与目标系统真正接受或完成。
2. 为关键名词、接口、状态、权限和完成条件形成单一契约，核对正文、步骤和验收口径。
3. 走查正常、并发、超时、取消、重启、重复、乱序、部分失败和旧数据场景。
4. 对关键状态转换说明写入者、读取者、唯一提交点、恢复者和幂等键。
5. 确认安全及所有权边界在查询、领取或执行前生效。
6. 将场景映射为可执行验收；仍有多个合规解释时，不准入实现。
7. 阻断项只列会影响正确性、安全、数据完整性或最终目标的问题。

**判断逻辑**：方案完成条件必须等于用户最终目标；文字要求只有在实现者能得到唯一行为时才算契约。崩溃安全、所有权隔离、原子性和恢复能力不能只靠风险说明或重试承诺。

**禁忌**：同一文档留有冲突行为让实现者自行选择；用本地提交代替远端接受、用消息构造代替投递；用内存回滚承诺崩溃恢复；执行后才检查跨渠道所有权；把未验证的平台能力当作既有事实。

**经验**：重要条款映射到状态机、持久化字段、调用边界或测试；异步业务考虑唯一业务键和可恢复 outbox；用“谁在什么时候能改变什么状态”挑战方案。

## 场景块 3：代码评审与增量复审

**适用条件**：评审 PR、提交、未提交工作树、修复增量或多轮修订的方案与实现。

**SOP**

1. 明确评审对象、基线、范围和工作树状态，避免混淆归因。
2. 按风险覆盖正确性、架构、安全、性能、兼容性和验证；每个发现写明触发条件、依据和影响。
3. 增量复审先核销上轮问题，再检查本轮风险，并说明是否完整重审。
4. 区分阻断、需修复和建议；不要把偏好包装成阻断，也不要因全量测试通过而忽略未覆盖边界。
5. 核对修复实现、调用方、测试及持久化/展示契约是否一致。
6. 验证范围与评审范围对齐，记录命令、数量、失败和环境限制。
7. 标明已确认、推断和未验证结论，结论绑定当前基线与范围。

**判断逻辑**：发现应可复现或可从代码路径严格推出，并说明实际后果。增量抽查不能描述成全量验收；测试通过是证据之一，不等于边界已覆盖。

**禁忌**：不记基线；把增量复审说成全分支复核；自动工具零输出或启动失败却称为通过；把沙箱限制归因于产品代码；为消除红灯恢复重复生产逻辑或降低验收断言。

**经验**：用短小证据链描述问题；复审表跟踪“上轮问题—本轮状态—证据”；区分代码失败、测试夹具问题和环境限制；保留真机、升级和外部服务未覆盖项。

## 场景块 4：测试设计与修复验收

**适用条件**：队列/配额/票据、并发请求、重试、恢复、迁移、安全门控、工具调用或多层协议变更。

**SOP**

1. 从契约推导不变量和终态，而不是只按实现分支罗列用例。
2. 添加复现原触发的回归测试，并覆盖相邻边界与跨层装配。
3. 顺序敏感状态覆盖乱序响应、并发抢占、重复事件、取消/超时和过期租约。
4. 对恢复或事务在持久化/文件操作边界注入故障，重启后检查状态。
5. 对队列、票据、配额生成确定性伪随机操作序列，逐步断言计数、上限和所有权不变量。
6. 保持原安全/产品验收断言；先确认测试夹具符合生产装配契约。
7. 按仓库策略运行受影响测试并记录范围；完整门禁按任务阶段执行。

**判断逻辑**：逐场景测试难以发现跨函数守恒问题，应与状态不变量测试并用。组件单测不能证明调用方接线；模拟不能证明真实客户端或操作系统行为。

**禁忌**：只测最终失败，不查重试状态、计数、归属和副作用；宽松 mock 替代真实解析和装配；为适配旧夹具恢复重复映射或降低断言；把模拟当成真机验收。

**经验**：写“状态序列 + 每步不变量”；安全边界测试断言无权相邻对象保持不变；故障注入横跨写入边界；测试夹具复用正式装配入口；定向测试命中改动，完整测试按仓库门禁运行。

## 场景块 5：数据迁移、持久化与崩溃恢复

**适用条件**：数据库/文件迁移、事件日志、压缩、备份、密钥迁移、工作树 apply、通知投递或声称原子/幂等/可恢复的功能。

**SOP**

1. 定义迁移前后不变量、唯一提交点、事务边界和幂等标识。
2. 列出每个外部副作用及其与数据库提交的顺序。
3. 对每个崩溃窗口推演重启后的磁盘状态，并定义唯一恢复动作。
4. 确认恢复材料崩溃后仍可识别、校验和重放；内存对象不能是唯一来源。
5. 在事务提交、文件写入/rename/fsync、消息插入/投递标记等边界注入故障。
6. 明确失败是回滚、可重试还是进入显式恢复状态；不能跳过后永久标记完成。
7. 比较迁移前后副作用，检查时间戳、顺序、审计和用户可见状态。

**判断逻辑**：原子性必须跨进程崩溃和重启成立；幂等键由持久唯一约束或等价原子协议落实；数据库引用的文件须先耐崩溃发布；失败不能伪装成完成。

**禁忌**：只在 catch 中恢复却声称支持崩溃恢复；跳过损坏数据仍写永久完成标记；把消息 ID 当成幂等保证却无唯一约束/outbox；用会刷新业务时间的通用 API 清理无关字段；数据库不可读时按不完整引用图做 GC。

**经验**：画持久化顺序和 crash matrix；每个副作用配恢复材料；迁移标记与数据更新同事务提交；数据库与文件系统双写考虑 outbox/journal；恢复路径可观测且可安全重试。

## 场景块 6：安全授权与外部渠道边界

**适用条件**：IM/远程工具、审批、密钥、用户内容、工作目录、执行工具或跨租户/跨渠道资源。

**SOP**

1. 写清威胁模型、受保护资产、主体身份、渠道/会话所有权和允许动作。
2. 在副作用前确认授权来自当前请求的有效策略版本和必要事实材料。
3. 为敏感内容评估失败或不确定定义 fail-closed 行为，确认后续路径不会放行。
4. 异步审批绑定请求、用户、会话、工具、nonce 和时效；执行前重新校验状态与授权。
5. 在查询、领取、发送、执行和重试各边界验证所有权，避免无权主体改变他人状态。
6. 检查日志、确认提示和错误文本的脱敏与可诊断性，不记录正文、token 或 secret。
7. 分别验证策略、集成接线和真实平台行为，标注未完成的真机验收。

**判断逻辑**：身份校验须发生在所有权状态改变之前；人工批准不覆盖独立的敏感内容终检；规则应由可信解析点产生，避免多层重映射。

**禁忌**：先领取或消耗重试额度，再发现事件属于其他渠道；把 unknown 当安全；审批覆盖后续敏感性检查；门控层重复解析策略；用模拟证明真实客户端行为；日志记录密钥或消息正文。

**经验**：fail closed、最小权限、授权与事实材料绑定版本、关键副作用前最终校验；跨边界测试检查其他渠道状态不变；真实外部能力单独验收。

## 场景块 7：阶段计划、范围控制与交付

**适用条件**：多阶段重构、清理、合并恢复、自动化任务、跨环境交付或高风险改动。

**SOP**

1. 开始前列出当前环境可验证项和需真机/外部系统验证项，定义交付形态。
2. 将目标拆成可独立验收阶段，写明输入、输出、准入条件和完成证据。
3. 先修阻断基线，再进入依赖它的重构/清理；hotfix 与结构变化分开。
4. 控制每阶段范围，评审结论绑定当前对象和基线。
5. 运行合适的定向验证，并按仓库约定补齐阶段或最终门禁。
6. 交付记录变更、验证、未完成外部边界和后续动作。

**判断逻辑**：阶段完成依据用户目标和可观察证据；独立缺陷先独立修复，降低归因和回滚成本；工作量与测试绿灯不是完成定义。

**禁忌**：收尾才暴露真机/外部验收；把迁移、删除、重构、测试清理和 hotfix 捆成难回退阶段；用局部完成掩盖最终目标未达成；覆盖或清理用户已有工作树改动。

**经验**：把可验证性纳入计划；每阶段留下可审查结果；保留用户工作树改动；区分计划完成、代码完成和外部验收完成。

## 横向长期原则

1. **证据先于叙述**：事实、推断、建议和未验证边界分开标记。
2. **契约唯一且可测试**：同一行为在文档、代码和验收中使用同一口径。
3. **边界前置**：权限、所有权、取消、提交和恢复在副作用前定义。
4. **状态可守恒**：队列、配额、重试、事件和审批有跨函数不变量。
5. **不因实现困难放宽验收**：先排查实现或夹具；标准仅随明确产品决策改变。
6. **恢复是产品路径**：崩溃、重启、重复和部分失败有明确状态与证据。
7. **环境验证分层**：说明单测、集成、构建、真机和外部服务各自证明范围。
8. **最小必要改动**：覆盖根因和相邻契约，避免无关回退或扩大范围。

## Agent 调用清单

任务开始时记录：

- 命中的场景块及触发条件；
- 本次要守住的契约或不变量；
- 最可能漏测的边界；
- 当前环境可验证的证据；
- 留给真机或外部系统的验收项。

长期知识只回写稳定的方法、规则或反例；提交号、一次性状态和进度留在来源或任务记录中，除非它们改变了可复用规则。
